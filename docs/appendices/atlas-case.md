# Atlas：合成贯穿案例

## 前提与时间线

虚构租户 tenant-demo 包含 atlas 项目及 u1、u2。两人均可读项目规范，只有 u1 可读其个人偏好。身份从认证层注入，客户端不能通过 scope 字段取得权限。

| 事件 | 有效日期 | 输入 | 应有行为 |
| --- | --- | --- | --- |
| E01 | 2026-10-01 | 手册 v1：普通发布需一人审批 | 建立规则 v1 |
| E02 | 2026-10-02 | u1 要求以后详细回答 | 建偏好 v1 |
| E03 | 2026-11-01 | 手册 v2：普通发布需两人 | 关闭旧有效期，创建后继 |
| E04 | 2026-11-02 | u1 要求以后先给简短结论 | 更正偏好 |
| E05 | 2026-11-03 | 只有一名审批者，能发布吗 | 规则判断未满足，偏好只影响表达 |
| E06 | 2026-11-04 | 查询 10 月 15 日要求 | 返回过去的一人规则并标时点 |
| E07 | 2026-11-05 | u1 删除答复偏好 | 阻断召回并清理派生物 |
| E08 | 2026-11-06 | 重放旧索引任务 | 版本和删除屏障阻止复活 |

有效区间为左闭右开 [from,to)。历史查询不绕过当前授权与删除屏障。

## 从输入到回答

E05 中，实时工具确认一人审批，知识要求两人，偏好不改变组织规则。回答可为“尚未满足普通发布要求，还缺一名审批者”，并引用 v2。若工具不可用，只能解释规则，不能断言当前状态。

若迟到 v1 副本晚于 v2 入库，不应覆盖 v2。若两个现行规范同样权威且互斥，应呈现冲突并核对，不能按最后拼接文本裁决。

## 执行恢复

文档页已远端创建但本地确认前崩溃：恢复先按幂等键或目标对象核对状态，不能直接再建一次。经验摘要保存教训，检查点和副作用账本保存可核对的执行事实。

## 删除完成

主记录 tombstone 表示即时访问阻断；向量、主题页、上下文缓存各自确认后才报告最终清理完成。共享摘要无法剥离则整体失效重建。备份按保留策略清除，恢复时重放删除账本。必须分开报告阻断与清理延迟。
