# 3.1 信息获取机制（Acquisition）

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

采集如何保留出处和权限？

连接器创建不可变来源快照，记录游标、版本与获取身份。处理与采集分离，失败可恢复，权限改变可定位受影响数据。

## 机制与细分考点

### 3.1.1 文档、网页及多模态数据

文档与网页保存结构和抓取版本；图片、音频保存原对象及文本定位。OCR 只是派生表示，不能替代原件。

### 3.1.2 用户对话与交互记录

对话保留说话者、会话、时间和顺序。引用内容需标明作者，不能作为当前用户授权。

### 3.1.3 Agent 行动轨迹和工具结果

行动轨迹保存参数、工具版本、状态和结果。成功返回码不等于任务目标达成，应核对实际结果。

### 3.1.4 外部 API 与业务数据库

API 与业务数据库使用稳定主键和增量序列，并处理删除事件；只拉当前快照会漏掉中间变化。

### 3.1.5 来源标识、去重及权限继承

来源 ID 与版本保证采集幂等，哈希辅助去重。相同内容跨权限域不能合并为公开对象。

## 推导与工程过程

连接器的增量游标只在来源快照可靠落盘后推进。若先推进游标再保存来源，崩溃会永久丢失事件；若先保存再推进，恢复时可能重复采集，可由来源 ID 与版本幂等消除。这里宁可允许可识别重复，也不允许静默丢失。

权限变化需要独立事件或定期核对，不能只在初次采集时读一次 ACL。来源内容未变但 ACL 变化时，内容哈希不变，因此以内容变化触发全部更新的设计会漏掉撤权。

手册与用户对话分别生成 Source；用户消息不继承项目手册的共享权限。
