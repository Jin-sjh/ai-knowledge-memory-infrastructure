# 3.5 信息价值判断（Information Selection）

[本章导读](README.md) · [可运行实验](../../labs/formation/README.md)

## 保存决策不能被一个重要性分数替代

本节区分四件事：内容是否有依据、是否允许保存、未来用途是否明确、当前调用者是否有权写入。高重要性不能抵消无权来源，频繁出现也不能让错误命题变真。

## 现有项目如何实现

Mem0 在提取提示中要求减少重复，同时在程序里比较旧召回集和当前批次的文本哈希；这两层去重不能互相替代。Letta 则通过核心文件与延迟目录分配有限上下文。它们都没有证明本书提出的全部价值维度已被统一解决。详见 [Mem0 的去重范围](../implementations/mem0.md)与 [Letta 的分层组织](../implementations/letta.md)。

### 3.5.1 知识提取粒度

粒度以独立验证、更新和复用为准。整份规范作为一个事实，局部变化会影响整份对象；拆成“2 人”“提交人”“审批”又丢掉逻辑关系。

实验把普通和紧急规则分别建模并保留来源。条件变化时能定位要改的记录，引用时又不丢完整语境。目标不是原子越小越好，而是足以独立维护。

### 3.5.2 记忆保存价值

记忆应能说明会怎样影响未来任务。项目答复偏好能改变未来呈现，一次性简短要求只约束当前任务。无法明确复用用途的细节，可以留在受治理的原始事件或待审核队列，不必全部进入长期召回索引。

TRANSIENT 是一种路由结论，不是低质量判定。本实验不实现临时会话服务，也不把未长期保存等同于已经从所有日志删除。

### 3.5.3 重要性、稳定性与复用价值

重要性描述影响大小，稳定性描述持续时间，复用价值描述未来使用机会。重要但瞬时的信息可能是状态，稳定但无关的信息也未必值得召回。

实验不用模型自报 0.95 自动批准，采用可解释保存依据。若未来增加价值评分，应先满足权限、证据与保存约束，再用开发集校准阈值，并在保留集分别报告误存和漏存。

### 3.5.4 信息冗余与噪声控制

重复投递、镜像、同义表达和不同条件需要不同处理。policy 重投在采集时去重；镜像有独立来源记录，但不增加独立证据数量；相同规范化内容写入 NOOP；普通与紧急条件不同则保持两个对象。

实验没有通用语义等价判定。NOOP 只比较经审核后的字段指纹，不能把高向量相似度直接变成自动合并。

### 3.5.5 自动写入与显式授权

自动保存必须有明确用途、主体和策略。拒绝保存是硬约束，模型不能通过 scope、approved 或自我打分赋予权限。候选 Schema 不接受这些字段。

读取许可、长期保存许可、调用外部模型的许可与写入许可是不同能力。实验输入是合成数据，真实应用必须独立检查这些授权，不能把一个笼统“允许处理”当全部许可。

### 3.5.6 提取成本与质量权衡

规则适合来源、结构、引用和权限检查；语义不确定性需要独立判定。模型或人工审核可处理难例，但都可能出错，也都有成本。

总成本还包含误存后的纠错、重建和删除，而非只看一次提取的 Token。实验把审核依赖公开出来，没有声称几行规则已经消除了审核工作。

## 一个可解释的决策顺序

推荐依次问：

1. 来源是否可读，记录和引用是否有效？
2. 候选是否有匹配版本的语义判定？
3. 是否允许长期保存，主体和范围是否一致？
4. 是否有明确未来用途或仍需独立验证？
5. 是否已经存在相同内容？
6. 调用者是否有写权限，预期版本是否匹配？

明确禁止保存始终优先。值得保存也不代表当前调用者有权执行保存；因此第六步在写入阶段再次检查。

## 四种输出，各自代表什么

| 决策 | 含义 | 后续动作 |
| --- | --- | --- |
| ACCEPTED | 通过当前场景策略 | 可提交写入，仍可能权限或版本失败 |
| TRANSIENT | 仅当前任务用途 | 交给会话或工作状态模块 |
| NEEDS_REVIEW | 依据、范围或方法适用性尚不充分 | 不发长期写入，保留未决原因 |
| REJECTED | 边界不合法或有明确反证 | 记录原因，不静默修复 |

NEEDS_REVIEW 不表示内容一定错误；REJECTED 也可能只表示当前主体无权使用。将原因保留下来，才能决定是补证据、重新授权还是直接丢弃。

## 同一规则的两种重复

policy@1 再次投递时无需重复解析。但 policy-mirror@1 是另一次来源观测，应该保留来源谱系和审计，不把它当第二份独立确认。

镜像的规范化内容相同，写入得到 NOOP；不会新增 Item 版本，也不会更新原证据集合。后者是实验边界：完整的多源支持关系需额外模型维护，不能把 NOOP 误读为已经完成知识融合。

fingerprint 比较 type、subject、predicate、value、conditions 与 content。只多一个例外也应使指纹变化，重新判定。数组条件顺序在当前实现中影响指纹，生产领域模型还需明确定义规范化。

## 为什么价值函数不能决定所有事

可以提出 V=重要性×复用概率×有效时长−维护成本，用来表达取舍。但这些量往往只是启发式，模型分数不是统计置信度。

即使“不要保存”这句话打分 100，也不能保存；无证据的“发布免审批”打分 1000，也不会变真。本实验使用离散理由，避免制造不必要的精确外观。

如果未来实验显示某类稳定候选可以低风险自动批准，应针对该类定义策略和误差预算，而不是全局降低门槛。

## 动手观察两种失败

~~~sh
npm run lab:formation -- --stage select
npm run lab:formation -- --stage write
~~~

先清空实验副本的 writable_scopes：选择可能依旧 ACCEPTED，但写入必须返回 WRITE_NOT_AUTHORIZED。再删掉 rule-normal 的判定：它应停在 NEEDS_REVIEW，而不是因项目来源已审核就自动通过。

修改来源元数据会改变 source_hash。不要自动重算哈希来“修复”失效判定，应该重新审阅变更；不然快照绑定便失去意义。
