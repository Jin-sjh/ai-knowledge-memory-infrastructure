# 3.4 记忆提取（Memory Extraction）

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

交互中什么值得成为记忆？

判断主体、稳定性、范围与未来用途，再区分显式偏好、一次性要求、事件和归纳经验。自我偏好与外部事实使用不同验证策略。

## 机制与细分考点

### 3.4.1 用户偏好识别

偏好记录主体、时间、明确程度和范围。隐式频率可增加候选价值，不能覆盖最新显式要求。

### 3.4.2 事件与经历提取

事件保留何时、谁做什么及结果，摘要链接原消息，避免把总结者解释当成用户原话。

### 3.4.3 Agent 任务经验提取

任务经验由行动与结果对照产生。Agent 自称成功不够，应查看目标状态和失败条件。

### 3.4.4 操作策略与程序性经验提取

程序性经验记录前提、步骤、结果与退出条件；推广到复用策略前需独立验证。

### 3.4.5 临时状态与长期记忆的区分

临时要求、游标和待办进入状态或短期工作集；稳定偏好和复用经验进入长期候选，类别不按文本长度决定。

## 推导与工程过程

对一条记忆候选保留 extraction_reason，例如 explicit_future_preference、observed_event 或 inferred_pattern。前两类有直接语句或事件证据，最后一类则是系统归纳，必须允许不确定。用户查看时应能区分“你说过”与“系统推测”。

程序性经验不要保存无边界的“遇到失败就重试”。应记录错误类型、可重试性、最大次数、幂等条件和停止后如何报告。操作策略一旦可能触发外部副作用，还需要执行系统重新授权。
