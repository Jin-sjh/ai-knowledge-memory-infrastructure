# 3.2 信息预处理（Preprocessing）

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

预处理怎样保住语义？

预处理改变表示但保留原始定位。清洗、切分和归一化均记录版本；无法解析的输入进入隔离队列，不能悄悄成为空文档。

## 机制与细分考点

### 3.2.1 文档解析

解析保留标题、列表、表头与脚注，并记录页码、节点路径或偏移，支持后续复核。

### 3.2.2 结构识别与 Chunking

识别结构后再切块，必要时补父标题与邻近窗口。重叠片段不应在证据统计中重复计数。

### 3.2.3 数据清洗与标准化

规范编码和重复页眉时保留否定词、单位与版本号。原文和规范化文本同时保留，以定位清洗误差。

### 3.2.4 时间、实体及上下文对齐

昨天、本项目、他依赖时间和主体语境。无法消歧时保留原表达与候选，而不是强行填值。

### 3.2.5 非可信输入与异常处理

输入中的指令属于数据，不升级为控制指令。失败有原因码、重试上限和人工复核入口，防止无限重试。

## 推导与工程过程

切块可以按“章节定位—结构单元—预算合并”三步进行。先确定标题路径，再保持段落、列表项和表格行组的完整，最后在 Token 预算内合并邻近单元。块过大时先按语义边界拆分，并保留共同父节点。不得为满足固定字符数把表头与数据拆开后丢掉关联。

评估切块除了 Recall@K，还要抽查引用是否包含充分条件、是否可定位到原件以及多块合并是否重复计费。不同解析器版本产生不同块 ID 时，旧向量应失效，而不是与新版混用。

## Atlas 案例

审批表格包含紧急发布例外，逐行抽文本若丢失表头，会把例外套在普通发布上。

## 适用条件与局限

解析质量随格式变化，应保留失败样本做专项评测。
