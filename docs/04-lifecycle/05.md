# 4.5 记忆演进

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

记忆如何演进而不制造错误？

区分内容更正、访问强化、压缩和删除。使用次数可调召回权重，却不能改变真值；衰减是一种激活策略，不等于删除。

## 机制与细分考点

### 4.5.1 记忆强化与更新

强化来自确认或有益使用，内容更新需要证据。错误记录不能因被反复召回而越来越可信。

### 4.5.2 记忆压缩和归纳

压缩检查主体、时间和例外是否保留，同时评测 Token 节省与任务质量，不能只看压缩率。

### 4.5.3 时间衰减与有效性

时间衰减可降低陈旧事件激活概率；明确有效期的规则仍按有效期判断，不能只按新旧排序。

### 4.5.4 记忆遗忘与删除

遗忘可指降权、失效或物理删除，接口必须明确；用户删除请求不能仅降权为零而保留可查副本。

### 4.5.5 经验向知识或策略的转化

经验升级为知识或策略需明确条件、独立验证和反例。一次排障成功不代表所有相似故障都适用。

## 推导与工程过程

衰减示意可写为 activation = base × exp(−λ × age)。它只控制召回倾向，不证明内容是否正确。程序手册可能很旧但仍有效；用户偏好可能昨天才写却今天已被明确更正。有效期、替代和删除应先于激活分数作为硬条件判断。

经验归纳可采用“事件集合—共同条件—候选策略—反例搜索—独立验证”的流程。没有验证时保留为建议，且在使用反馈中记录失败，避免成功案例不断强化而失败案例被摘要丢失。
