# 4.5 记忆演进

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

记忆如何演进而不制造错误？

区分内容更正、访问强化、压缩和删除。使用次数可调召回权重，却不能改变真值；衰减是一种激活策略，不等于删除。

### 4.5.1 记忆强化与更新

一次记忆被多次召回，说明它常与查询相关，并不证明内容正确。错误摘要也可能不断命中，若每次命中都提高可信度，就会自我强化。

更新应区分使用频次、效果反馈和本人确认。重复成功可以提高检索优先级，但仍保留原始依据；明确更正到来时，应重新判断当前默认，而不是让旧记忆凭累计次数压过新表达。

### 4.5.2 记忆压缩和归纳

将“仅在 Atlas 汇报时先给简短结论，追问再展开”压成“用户喜欢简短”，减少了字数，也删除了项目和触发条件。压缩是否成功，应看决定行为的语义是否保留，而不只看长度。

先列出不能丢失的主体、范围、时间、条件及例外，再核对摘要。原文仍是纠错依据，摘要要绑定输入版本；更正后重建，而不是认为长期保存的摘要自然有效。

Letta Code 的核心记忆投影与深层文件读取提供了分层放置的实例。可以把稳定摘要放入核心，详细事件留在深层，但摘要需要关联来源并随更正重建。分层减少常驻输入，不代表摘要自动正确，也不代表未读取资料已参与推理。[固定版本源码](https://github.com/letta-ai/letta-code/blob/bd31b0a72dfad1ba14fc3a82f47da6a2b606330d/src/backend/local/system-prompt-compilation.ts#L65-L198)。

### 4.5.3 时间衰减与有效性

“今天赶时间”可以随任务结束失效，“默认用中文”则可能长期适用。时间衰减不宜对所有记录使用同一公式，否则稳定偏好会被无故遗忘，临时事件又可能保留过久。

可以把时间作为排序因素，同时用明确有效期和替代关系决定资格。最新记录也可能是今天导入的旧对话，业务发生时间与采集时间要分开；旧不等于错，新也不等于适用。

衰减示意可写为 activation = base × exp(−λ × age)。它只控制召回倾向，不证明内容是否正确。程序手册可能很旧但仍有效；用户偏好可能昨天才写却今天已被明确更正。有效期、替代和删除应先于激活分数作为硬条件判断。

经验归纳可采用“事件集合—共同条件—候选策略—反例搜索—独立验证”的流程。没有验证时保留为建议，且在使用反馈中记录失败，避免成功案例不断强化而失败案例被摘要丢失。

### 4.5.4 记忆遗忘与删除

遗忘可以指不再激活、归档或物理删除，三者应明确区分。降低召回分数不能满足“删除偏好”的要求，因为记录仍可能被宽查询、缓存或摘要使用。

删除请求先阻止在线使用，再沿依赖清理副本并记录确认；无法立即清理的备份按保留策略处理。对外说明完成范围，不能把主库删除成功等同所有历史副本消失。

### 4.5.5 经验向知识或策略的转化

一次回退解决故障，只能支持“该情景下采取该行动后恢复”。提升为通用策略前，需比较环境、排除其他同时变化因素，并通过复现或领域审核限定适用范围。

参考流程保留经历，生成方法候选，再记录验证和批准。共享时还要去除私有信息并重新授权；个人经验变成团队知识，既是语义提升，也是治理范围变化。
