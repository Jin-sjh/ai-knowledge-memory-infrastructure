# 4.5 记忆演进

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。资料核验日期：2026-11-13。

## 要解决的问题

记忆如何演进而不制造错误？

区分内容更正、访问强化、压缩和删除。使用次数可调召回权重，却不能改变真值；衰减是一种激活策略，不等于删除。

### 4.5.1 记忆强化与更新

一次记忆被多次召回，说明它常与查询相关，并不证明内容正确。错误摘要也可能不断命中，若每次命中都提高可信度，就会自我强化。

更新应区分使用频次、效果反馈和本人确认。重复成功可以提高检索优先级，但仍保留原始依据；明确更正到来时，应重新判断当前默认，而不是让旧记忆凭累计次数压过新表达。

### 4.5.2 记忆压缩和归纳

#### 摘要错误为什么会反复回来

三次表达分别是 e1“Atlas 汇报请详细”、e2“今天赶时间先给结论”、e3“以后 Atlas 先给结论，追问再展开”。直接统计“先给结论”出现两次，会得到一个看似高频的简短偏好，却无法分辨临时要求与长期更正。

巩固先把 e2 绑定到当天任务，将 e3 解释为对默认的更正，再生成当前摘要。摘要应保留 Atlas 范围与追问条件，并记录依赖 e1、e3；e2 可以留作情景，但不必成为长期默认依据。统计频次可以辅助选择，不应替代语义与意图判断。

若旧摘要 s1 已写成“用户总喜欢详细”，后续只追加 s2 而不退出 s1 的当前用途，两条摘要都会继续被召回。巩固因此包含发布和失效：新摘要通过核对后成为当前视图，旧摘要仍可用于授权历史解释，但不再作为默认指令。

Letta Code 的核心记忆投影与深层文件读取提供了分层放置的实例。可以把稳定摘要放入核心，详细事件留在深层，但摘要需要关联来源并随更正重建。分层减少常驻输入，不代表摘要自动正确，也不代表未读取资料已参与推理。[R15][固定版本源码](https://github.com/letta-ai/letta-code/blob/bd31b0a72dfad1ba14fc3a82f47da6a2b606330d/src/backend/local/system-prompt-compilation.ts#L65-L198)。

### 4.5.3 时间衰减与有效性

“今天赶时间”可以随任务结束失效，“默认用中文”则可能长期适用。时间衰减不宜对所有记录使用同一公式，否则稳定偏好会被无故遗忘，临时事件又可能保留过久。

可以把时间作为排序因素，同时用明确有效期和替代关系决定资格。最新记录也可能是今天导入的旧对话，业务发生时间与采集时间要分开；旧不等于错，新也不等于适用。

例如，两条故障经历都通过权限、有效性和场景检查后，可以用时间权重辅助排序。一个纯示意规则是“每过两天，时间权重减半”：发生当天为 1，两天后为 0.5，四天后为 0.25。两条经历其他评分相同且以该权重相乘时，较新的会更靠前；较旧的仍可能因更符合当前环境而被选中。

这里“两天”是演示参数，不是推荐默认值，也不是通用记忆规律。真实系统需用任务数据判断时间是否有帮助，再选择衰减速度；明确的长期偏好可以不采用这种衰减。

先检查是否允许使用，再调整排序。已删除或已被替代的记录不能只降权后继续作为当前依据；仍有效的旧手册也不能仅因年久而被判错。

### 4.5.4 记忆遗忘与删除

遗忘可以指不再激活、归档或物理删除，三者应明确区分。降低召回分数不能满足“删除偏好”的要求，因为记录仍可能被宽查询、缓存或摘要使用。

删除请求先阻止在线使用，再沿依赖清理副本并记录确认；无法立即清理的备份按保留策略处理。对外说明完成范围，不能把主库删除成功等同所有历史副本消失。

### 4.5.5 经验向知识或策略的转化

一次回退解决故障，只能支持“该情景下采取该行动后恢复”。提升为通用策略前，需比较环境、排除其他同时变化因素，并通过复现或领域审核限定适用范围。

参考流程保留经历，生成方法候选，再记录验证和批准。共享时还要去除私有信息并重新授权；个人经验变成团队知识，既是语义提升，也是治理范围变化。

归纳时主动寻找反例，并记录失败反馈。否则成功经历不断被强化，失败条件却在摘要中消失，最终会把局部经验误写成通用方法。
