# 5.1 信息访问基础

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

不同查询应该走哪条访问路径？

先识别查询意图与精确约束，再选择 SQL、全文、向量、图或直接阅读。检索技术是互补工具，所有路径都要经过相同可见性与时态约束。

## 机制与细分考点

### 5.1.1 精确查询与 SQL / API

SQL/API 适合已知 ID、精确过滤和聚合。模型生成查询需约束权限与语句类型，数值汇总不应交给文本相似度猜测。

#### 精确读取与语义查找的分工

问“u1 当前答复风格是什么”时，主体和属性已经确定，优先按键读取当前档案。问“过去哪次发布遇到类似问题”时，目标事件未知，才需要关键词、语义或关系检索。把前者交给相似度排名，会引入不必要的漏召回和旧版竞争。

官方 LangGraph 示例按 namespace/key 读取偏好，不需要 embedding；Store 的使用不等于向量搜索。实现联合访问时，可让精确档案和项目文档走不同路径，在候选已经完成授权后再合并。性能与正确率应分别测量。 [固定版本源码](https://github.com/langchain-ai/langgraphjs/blob/959f041dfb8f6bbafa6af3ebb4bc20484a9290da/libs/checkpoint/src/store/memory.ts#L188-L219)。

### 5.1.2 关键词与全文检索

关键词检索适合错误码、专有名词和精确措辞。分词、字段权重与同义词影响效果，中文与代码混合内容需专项验证。

### 5.1.3 Embedding 与语义检索

Embedding 支持同义表达，但可能混淆否定、数字与时间。必须携带原记录并复核约束，不能只返回无出处文本。

### 5.1.4 Hybrid Search

Hybrid Search 合并不同召回集合，可用 RRF 按排名融合；不同检索器原始分数不能直接相加。融合后再统一过滤和排序。

### 5.1.5 图关系与路径查询

图查询适合关系路径和依赖追踪，需要限制跳数、边类型和权限，避免路径爆炸以及通过隐藏节点泄露关系。

### 5.1.6 Long Context 与直接阅读

小而已知的文档集合可直接放入长上下文。窗口容得下不等于模型利用充分，位置敏感性需在目标模型重新验证。[R05]

## 推导与工程过程

RRF 的一个参考形式为 score(d)=Σ 1/(c+rank_r(d))，只对检索器返回的文档累加，缺席项不加分。示例 c=60，d1 排名为 1 和 20，得分约 0.02889；d2 排名 3 和 2，约 0.03200。因此 d2 更靠前。c 是需要开发集选择的参数，不是固定最佳值。

融合使用排名避免直接混加 BM25 和余弦分数，但不能补偿权限错误、索引漏召回或错误文本。融合前后都保留检索器排名，便于解释最终结果。

## Atlas 案例

查询审批人数优先读取当前有效规则；查询与上次故障类似的经历可走语义检索；查询依赖影响可走关系图。

## 适用条件与局限

索引选择需要目标数据评测，不能凭语义检索这个名称判断优劣。
