## 要解决的问题

RAG 的变化究竟改变了什么？

RAG 在生成前或生成过程中获取外部证据。原始 RAG 论文提供参数与非参数信息结合的一种研究形式，工程中常用的 RAG 是更广的流水线称呼。[R01]

## 机制与细分考点

### 5.2.1 RAG 的定义与工作机制

RAG 将检索结果作为生成依据，评测必须拆开检索覆盖与生成忠实度；正确答案不一定意味着检索成功。

### 5.2.2 Naive RAG

Naive RAG 通常切块、向量召回、拼接后生成，便于建立基线，但易丢上下文、版本和实体约束。

### 5.2.3 Advanced / Hybrid RAG

Advanced/Hybrid 常加入查询改写、多路召回与重排。每个模块都增加成本，应以消融判断收益而非默认堆叠。

### 5.2.4 Hierarchical RAG

Hierarchical RAG 先选文档或主题再选片段，减少局部块丢失全局语境的问题，但上层路由漏选会阻断后续召回。

### 5.2.5 GraphRAG

GraphRAG 可利用实体关系及社区摘要支持全局主题查询；不能把论文特定方案的收益推广到所有图检索。[R04]

### 5.2.6 Agentic RAG

Agentic RAG 让 Agent 决定下一步检索或工具调用，需限制轮数、成本和停止条件，防止循环搜索或被材料指令影响。

### 5.2.7 检索召回、重排序与证据覆盖

召回扩大候选，重排精选证据，覆盖检查确认问题各子项都有支持。重排无法找回从未被召回的关键依据。

## 推导与工程过程

排查 RAG 错误按顺序检查：金标准证据是否入库；是否被候选召回；是否被重排留下；是否进入最终上下文；答案是否正确引用。每一阶段保存对象 ID 与版本，便于做漏斗分析。只记录最终答案无法区分检索失败与生成失败。

Agentic 检索的停止条件可为已覆盖全部子问题、预算耗尽、连续调用无新增证据或需要人工澄清。若只有轮数上限而没有证据覆盖标准，系统可能早停；若只追求覆盖而没有预算，则可能陷入搜索循环。
