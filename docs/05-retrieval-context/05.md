# 5.5 知识与记忆联合访问

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。资料核验日期：2026-11-13。

## 要解决的问题

知识、记忆和状态如何联合访问？

查询规划分解所需信息，多源检索后统一做授权、有效性、冲突与证据充分性检查。最终回答说明结论适用的主体与时间，不将多源文本扁平拼接。

### 5.5.1 多源检索与查询规划

联合查询先形成计划：需要规范、偏好还是实时状态，各自用什么身份与时点访问。可独立分支并行读取，但某些查询依赖前一步确定的项目或对象，不能盲目同时发出。

计划还应定义失败行为。例如偏好缺失可用默认表达，规范缺失则不能确认许可；把所有异常都转成空结果会掩盖重要差异。

### 5.5.2 Knowledge + Memory Retrieval

问“能否发布，简短回答”时，规范决定许可条件，审批状态说明条件是否满足，偏好决定表达方式。先分别取回并核对，再合成答案，不能让用户过去的习惯覆盖业务规则。

即使最终只回答一句话，后台也需要完整依据。简短可以省去背景，不能省掉“审批尚未满足”这样决定结论的信息。

本书建议返回带用途的候选：policy、preference、execution_state，并保留各自来源与版本。合并阶段检查时间和权限，装配阶段才决定长度。LangGraph 的独立 Store 与检查点示例可验证两路数据的分工，但它没有实现本节完整联合检索服务。[R16][固定版本源码](https://github.com/langchain-ai/langgraphjs/blob/959f041dfb8f6bbafa6af3ebb4bc20484a9290da/libs/checkpoint/src/store/memory.ts#L188-L219)。

可以把这次查询展开为以下参考访问计划，所有分支在可信身份约束下执行。

| 分支 | 输入 | 需要的输出 | 缺失时的处理 |
| --- | --- | --- | --- |
| 项目规则 | project_id、业务时点 | 有效规则及证据 | 不判断是否允许发布 |
| 用户偏好 | user_id、project_id | 当前有效表达偏好 | 使用产品默认表达 |
| 任务状态 | run_id、checkpoint 版本 | 审批完成情况 | 先核对业务状态 |
| 装配 | 三路授权结果 | 结论依据与表达约束 | 显式列出未确认项 |

三路都返回不代表一定能回答。规则要求两人审批，而状态只有“一人已审批”时，应明确指出条件未满足；偏好要求简短也不能删除这个决定性理由。

联合回答可保留三列表：规则约束、当前观测、用户呈现偏好。发布是否满足由前两者比较决定，第三者只决定表达。若当前观测不存在，系统可给条件式结论“若只有一人则未满足”，而不能把用户问句直接当作已经核验的工具事实。

最终输出门检查每个引用对象的当前权限和删除状态，避免构造期间发生撤权后的竞态。若权限已变，丢弃受影响上下文并重新组装，而不是仅移除引用标签却保留泄露文本。

### 5.5.3 State / Tool / Knowledge 联合上下文

检查点说明任务执行到哪一步，工具结果说明业务系统当前观察，知识说明应满足什么要求。例如游标显示审批检查已执行，不证明审批此刻仍有效。

联合时核对对象、时间与版本，区分保存状态和实时事实。恢复任务后若关键业务状态可能变化，应重新确认，而不是把旧检查点当作永久授权。

### 5.5.4 来源与权限过滤

每条候选进入合并前都要核对来源与读取者权限，缓存和派生摘要也要纳入。用户可以读项目手册，不代表可以读生成某段总结时使用的其他成员私有信息。

参考实现用可信身份派生范围，并回查候选当前状态。仅在提示中写“不要泄露”不能替代数据访问控制，因为越权内容已经进入输入。

### 5.5.5 冲突信息与过期信息处理

新旧规则同时命中时，先检查有效区间和替代关系；当前查询排除过期版本，历史查询则选择相应时点。真正未决的冲突要连同依据返回，不应悄悄挑最高分。

若缓存仍持有旧规则，应失效或重新装配。过滤只作用于新检索而不检查缓存，会让系统在同一问题上返回不同治理状态。

### 5.5.6 拒答、证据不足与不确定性

#### 同一请求的三种缺口，需要三种回答

用户问“现在能发布吗，先给结论”。规范查询返回双人要求，用户偏好返回先给结论，但审批 API 超时。系统可以确认规范要求，不能确认当前状态；合理回答是“暂不能确认，需核实两名合格审批者是否完成”，而不是把超时解释成审批未完成或允许发布。

若状态可读但只有一名合格审批者，结论不同：已知条件未满足，应明确指出缺少第二人。若状态显示两人，规范却有两个同时有效的矛盾版本，则缺的是规则裁决，不能靠状态完整来补足。

偏好缺失通常可以采用产品默认表达，不必让整题失败。这说明分支重要性由任务决定：表达方式可降级，许可依据不能凭空补齐，执行状态也不能被旧聊天代替。

参考返回除答案材料外还带缺口类别、失败分支与下一步。应用据此询问、补查或限制动作；用户看到的文本不必暴露内部字段，但应清楚区分“已知不满足”“尚未查到”和“材料互相矛盾”。
