# 5.3 记忆召回机制

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

记忆召回与一般文档检索有什么不同？

记忆检索增加主体、事件时间、偏好有效期与程序前提等约束。先用硬条件确定允许使用的集合，再用相关性和任务价值排序。

## 机制与细分考点

### 5.3.1 Memory Retrieval

Memory Retrieval 明确查询主体、作用域、时间与目的，可返回语义、情景和程序候选，但保持各自类型。

### 5.3.2 相关性与重要性排序

相关性说明与问题接近，重要性说明影响大小；两者可形成加权启发式，但需用真实任务调参，不能宣称统一最优。

### 5.3.3 时间感知检索

时间感知检索区分事件时间、有效时间与入库时间；过去时点查询使用 as_of，迟到事件按有效期处理。

### 5.3.4 偏好、情景与程序性记忆召回

偏好按当前适用范围召回，情景按事件与时间召回，程序按前提和环境召回。一个统一相似度阈值难兼顾三者。

### 5.3.5 记忆激活、过滤及抑制

激活提高当前候选权重，过滤排除不合法记录，抑制降低干扰。已删除、撤权与失效对象应硬排除，不能仅降权。

### 5.3.6 错误记忆对推理的影响

错误记忆会让生成在错误前提上保持内部连贯，甚至压过正确工具结果。应评测有毒记忆注入与纠错后的残留影响。

## 推导与工程过程

排序可用 s=α·relevance+β·importance+γ·recency，但先过滤 tenant、主体、权限、有效期和删除状态。若先按全库 TopK 再过滤，合法结果可能不足 K；应使用预过滤、扩大候选或迭代检索，并测过滤选择性对召回的影响。

程序性记忆还需要前提匹配。例如只适用于测试环境的重置步骤，不得因文本高度相似而进入生产行动计划。召回结果应显示前提与验证状态，应用再次核验实际环境。

## Atlas 案例

Atlas 回答当前发布问题时使用现行规则和 u1 当前偏好；问去年为什么失败时则检索过去事件，不应用当前偏好覆盖历史。

## 适用条件与局限

高频使用不代表真实，高相似度也不代表适合当前任务。
