# 5.3 记忆召回机制

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。资料核验日期：2026-11-13。

## 要解决的问题

记忆召回与一般文档检索有什么不同？

记忆检索增加主体、事件时间、偏好有效期与程序前提等约束。先用硬条件确定允许使用的集合，再用相关性和任务价值排序。

### 5.3.1 Memory Retrieval

记忆召回先判断当前任务需要哪类历史，再选择访问路径。精确偏好可以按主体与属性读取，类似故障经历可以语义搜索，操作方法要匹配环境前提。

召回不是把最相似的旧聊天直接加入提示。每个候选还要核对范围、有效状态及用途；被保留的历史不一定有资格影响当前行为。

### 5.3.2 相关性与重要性排序

相关性表示内容与问题接近，重要性表示它值得关注，两者都不证明适用。一次严重事故可能很重要，却发生在不同产品；一条新偏好很短，却决定当前表达方式。

先做资格筛选，再排序；对需要精确服从的现行规则，可给予独立通道，而不是让其与普通经历竞争同一个 Top-K。

### 5.3.3 时间感知检索

#### 新写入的记录不一定代表新的偏好

设 e1 是周一明确的“Atlas 默认详细”，e2 是周三明确的“以后先给结论”，e3 是周五导入的一段上周对话，再次提到详细。按记录更新时间排序，e3 最新；按本人表达发生时间，e2 才是当前更正。

读取时先确认 e3 的时间是否可靠，再核对其主体与范围。确认它是历史导入后，将它放回原事件顺序，而不是用周五的入库时间覆盖当前档案。如果原对话没有可靠时间，保留不确定性；不能为了决定唯一当前值自行猜测。

若 e2 写的是“今天先给结论”，它只影响当天任务，不建立长期替代；若写的是另一个项目，则两条默认并存。时间排序必须在主体、属性、范围与变更意图已确定后使用，不能独立承担所有裁决。

Mem0 添加路径把部分旧记忆提供给提取器，可能帮助候选表达变化背景，但候选文本里出现“改为”不等于已形成受管理的有效区间。接入当前偏好查询时，应明确由写入投影还是读取裁决完成这一步，并检查缺少旧召回时仍能怎样处理。

Mem0 写入会召回旧记忆辅助提取，这不等于最终回答阶段已经实现上述裁决。接入时需追踪“旧候选被取回、被过滤、被装配”的每个位置，避免只查看存储里有新版就认为召回策略正确。[R14][固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

排序可用 s=α·relevance+β·importance+γ·recency，但先过滤 tenant、主体、权限、有效期和删除状态。若先按全库 TopK 再过滤，合法结果可能不足 K；应使用预过滤、扩大候选或迭代检索，并测过滤选择性对召回的影响。

程序性记忆还需要前提匹配。例如只适用于测试环境的重置步骤，不得因文本高度相似而进入生产行动计划。召回结果应显示前提与验证状态，应用再次核验实际环境。

### 5.3.4 偏好、情景与程序性记忆召回

偏好用于调整响应，情景用于提出线索，程序用于指导步骤。面对发布失败，可读取当前偏好以决定先给结论，召回历史故障以构造排查方向，再核对操作方法的版本条件。

三类结果应标明用途，不能把历史解决方法当作当前已证实原因，也不能让简短偏好删除必要的风险和执行前提。

### 5.3.5 记忆激活、过滤及抑制

激活是选择当前可用的记忆，抑制是阻止某些记录参与本轮。例如旧偏好仍可历史查询，却不应与新版一起作为默认指令。

参考流程先按主体、范围和治理状态筛选，再处理更正关系及排序。只降低旧记录分数不一定能阻止其使用；明确替代或删除应成为资格约束。

#### 三条相关记忆，不应同时成为默认指令

用户当前询问 Atlas，系统得到三个候选：m1 是以前的详细默认，m2 是已明确更正的“先给结论、追问展开”，m3 是另一个项目的一句话偏好。

m1 因替代关系退出当前默认用途，但保留授权历史查询；m2 进入本轮装配；m3 因项目范围不符排除。若本轮另有“这次详细展开”，遵循当前要求且不改写 m2。这里先按资格选择，再排序，不是简单给新记录多加一点时间分数。

### 5.3.6 错误记忆对推理的影响

错误记忆进入上下文后，可能使模型以为结论已有历史支持。例如一次错误摘要写成“所有发布只需一人”，后续每次召回都会强化相同答案。

纠错要定位原始来源，修正记录与派生摘要，并检查缓存是否仍含旧文本。仅在最新一轮解释正确，不代表后续访问已经消除影响。
