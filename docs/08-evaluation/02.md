# 8.2 记忆质量评测

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

记忆质量怎样避免只测记住多少？

把应保存、应召回、应更正和应忘记分别建立金标准。记忆数量不是收益，任务改善和错误影响才决定价值。[R06]

### 8.2.1 Memory Precision

Memory Precision 衡量保存或召回的记忆有多少符合预定标准，必须说明评测对象。保存阶段关注是否值得保留且解释正确；召回阶段关注本次是否适用。

例如十条候选中六条应长期保存，系统保存八条且五条正确，才能按该口径计算。数字是手算示意；临时要求被提成长偏好应计为范围错误，而非仅看文本相关。

### 8.2.2 Memory Recall

Memory Recall 需要先定义哪些历史在当前任务必须找回。例如回答更正后的偏好，需要现行表达及必要关系，不是找回所有聊天。

测试集应包含未出现过的表述、不同主体和过期干扰，按事件链标注必要记忆。缺少完整金标准时说明覆盖范围，不把未标注内容自动当成不相关。

### 8.2.3 Memory Utility

#### 怎样证明是记忆带来了帮助

同一问题“分析 Atlas 的变化”在两个条件下回答：条件 A 不提供长期偏好，条件 B 提供经确认的先给结论偏好。模型、问题和其他材料保持一致，并记录实际输入及输出。比较的是表达要求是否被满足，同时检查内容正确性没有下降。

如果 B 只是比 A 多了一大段任务相关资料，改善可能来自额外知识而非个人记忆；如果人工直接写入完美偏好，又不能据此评价自动提取效果。因此分别设置理想记忆与实际形成记忆，可以观察读取收益和形成误差。

还应加入错误、过期及无关记忆条件。系统在正确记忆下获益，却被旧偏好轻易误导，说明收益依赖治理质量。平均分需要与纠错题、范围题和撤回题一起报告。

当任务不需要个人信息时，启用记忆可能没有收益，甚至只增加 Token。效用评测允许得出不启用的结论；目的不是证明所有任务都需要记忆，而是确定在哪些条件下值得保存与使用。

记忆收益使用配对差异：同一任务在相同模型与预算下，比较启用和不启用记忆的结果。改善可能来自正确偏好，也可能因额外 Token 造成偶然差异，所以要保留输入、重复运行并按任务类别分析。

删除评测同时包含目标残留与无关误删。删除 u1 偏好后，项目规则应仍可读；若系统直接清空整个索引，残留为零却破坏知识能力，不能算完整成功。

公开长期记忆基准可补充通用能力评测，但不能替代本系统的权限与删除测试。

### 8.2.4 Temporal Consistency

用有顺序的事件测试时间一致性：先建立详细默认，再给本次简短要求，随后长期改为先给结论，最后撤回。每个时点分别查询当前和历史，核对范围及版本。

保存新版只是一个断言，还要检查旧版是否错误激活、最终输入采用什么。今天导入旧记录不应覆盖较新的本人表达，因此测试需区分发生时间和记录时间。

Mem0 的追加记录使“已保存更正”与“回答使用更正”成为两项指标。应分别测新信息保存率、旧信息错误激活率和删除后残留率。LangGraph 的现有示例只覆盖确定性读写，不构成这些模型层指标的结果。[固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

### 8.2.5 Forgetting / Correction Accuracy

更正评测检查新版被采用且旧版不再影响当前默认；删除评测还要检查主库、索引、摘要、缓存等副本及访问路径。两者不宜只看删除 API 返回成功。

同时验证无关对象未被误删。清空整个索引会让目标残留为零，却损害项目知识，不能算正确；历史保留是否允许则按产品承诺单独判定。
