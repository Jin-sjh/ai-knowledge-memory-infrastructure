# 8.2 记忆质量评测

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

记忆质量怎样避免只测记住多少？

把应保存、应召回、应更正和应忘记分别建立金标准。记忆数量不是收益，任务改善和错误影响才决定价值。[R06]

## 机制与细分考点

### 8.2.1 Memory Precision

Memory Precision 是正确且允许保存的记忆占所保存记忆比例，需把误归属、越范围和错误内容都算入失败。

### 8.2.2 Memory Recall

Memory Recall 是应保存金标准中被正确保存的比例；必须预先标注应保存集合，不能用模型输出本身定义分母。

### 8.2.3 Memory Utility

Utility 用有无记忆的同任务配对差异衡量，包括成功率、干扰和成本，不能只统计召回次数。

### 8.2.4 Temporal Consistency

Temporal Consistency 检查当前与历史时点回答是否正确；将事件顺序、更正、迟到信息单独设组。

#### 用更正序列验证时间一致性

设计一条未运行的参考用例：t1 详细偏好，t2 仅本次简短，t3 长期改为简短，t4 删除偏好。分别在每个时点询问当前与历史偏好，并检查适用范围。每个断言保存输入事件、期望视图、实际召回和最终上下文。

Mem0 的追加记录使“已保存更正”与“回答使用更正”成为两项指标。应分别测新信息保存率、旧信息错误激活率和删除后残留率。LangGraph 的现有示例只覆盖确定性读写，不构成这些模型层指标的结果。 [固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

### 8.2.5 Forgetting / Correction Accuracy

Forgetting/Correction Accuracy 检查删除后残留召回、更正后旧值使用，以及误删无关内容，分别报告而非混成单分数。

## 推导与工程过程

记忆收益使用配对差异：同一任务在相同模型与预算下，比较启用和不启用记忆的结果。改善可能来自正确偏好，也可能因额外 Token 造成偶然差异，所以要保留输入、重复运行并按任务类别分析。

删除评测同时包含目标残留与无关误删。删除 u1 偏好后，项目规则应仍可读；若系统直接清空整个索引，残留为零却破坏知识能力，不能算完整成功。

## Atlas 案例

用户由详细改为简短后，用新问题检查当前偏好，再问过去偏好检查时间线；删除后检查所有入口是否残留。

## 适用条件与局限

公开长期记忆基准可补充通用能力评测，但不能替代本系统的权限与删除测试。
