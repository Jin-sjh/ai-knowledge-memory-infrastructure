# 8.5 系统工程指标

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

成本、性能和可靠性如何一起报告？

区分离线构建、在线查询与持续维护成本。使用固定数据与并发配置，记录冷启动、稳态和故障期间表现，避免只展示最好一次。

## 机制与细分考点

### 8.5.1 查询延迟与吞吐

延迟报告 p50/p95/p99 与样本数，吞吐注明并发和错误率；将检索、重排、生成分段计时。

### 8.5.2 Token 与推理成本

Token 成本包含提取、构建、检索改写、裁判和生成；记录模型版本、单价日期和失败重试，单独报告离线和在线。

### 8.5.3 存储和索引维护成本

存储计入来源、副本、向量、图和日志，维护计入重建与删除任务；按更新频率摊销，不能只看静态容量。

### 8.5.4 可扩展性

扩展实验逐步增加数据量、并发与更新率，观察质量、尾延迟和积压，避免将单机小样本外推到生产。

### 8.5.5 可靠性与运维复杂度

可靠性记录成功率、恢复时间与数据丢失窗口；运维复杂度包括告警、值班和迁移，不应只以服务数量代替。

## 推导与工程过程

p95 应注明样本数、并发、超时和失败如何计入。若只统计成功请求延迟，最慢的超时请求被排除后会得到虚假的改善。分别报告成功分布、超时率和总体服务目标达成率。

总成本可写为 Ctotal=Cbuild+Cupdate+Cquery+Cjudge+Coperations。对固定时间窗口按实际查询量摊销，并同时保留绝对成本；查询量极少时，预构建大型主题图谱可能不经济。
