## 要解决的问题

典型场景的成功标准有什么不同？

场景决定信息价值、错误代价和评测单位。共享底座不意味着采用同一保存策略或统一成功指标。

## 机制与细分考点

### 8.7.1 企业知识问答系统

企业问答重视出处、权限和时效；成功包括回答正确、引用支持及不泄露，不能只看可读性。

### 8.7.2 AI Coding Agent

Coding Agent 需要仓库版本、符号和测试结果，过去解决方案需核对当前代码。以实际修复与回归测试评估，不凭解释流畅度。

#### Coding Agent 的验收场景

准备两个项目，各有不同构建命令；用户先说明项目 A 的惯例，随后切换项目 B。检查 Agent 是否按当前项目读取资料，而非把 A 的命令迁移过去。再修改惯例文件但暂不提交，核对当前轮与后续轮分别使用哪个快照。

Letta Code 的已提交核心投影与工作区按需读取使快照差异成为可测试问题。实验必须记录提交 ID、工作区状态和工具读到的文本；答案中出现正确命令，仍需排除模型凭先验猜中的可能。此处是验收设计，不声称已跑过完整 Agent。 [固定版本源码](https://github.com/letta-ai/letta-code/blob/bd31b0a72dfad1ba14fc3a82f47da6a2b606330d/src/backend/local/system-prompt-compilation.ts#L65-L198)。

### 8.7.3 长期运行的任务 Agent

长任务 Agent 需要检查点、外部副作用账本与恢复，经验支持策略选择，不能代替精确执行状态。

### 8.7.4 个人知识管理系统

个人知识系统重视可编辑、可导出与隐私控制，保存价值由用户目标决定，不能把所有阅读都强制变长期记忆。

### 8.7.5 多 Agent 协作系统

多 Agent 系统需要共享范围、并发版本和来源归属，独立 Agent 的重复总结不算多个独立证据。

## 推导与工程过程

每个应用建立损失函数前，先列不可接受失败。例如企业问答不能跨部门泄露，Coding Agent 不能把别的提交结果当当前测试，长任务不能重复副作用。然后再优化一般成功率。平均指标掩盖低频高代价错误时，按场景分层报告。

多 Agent 的共识也需核对信息独立性。三个 Agent 若都读取同一错误摘要，三次一致回答不形成三个独立证据，应追踪到底层来源。

## Atlas 案例

Atlas 可以服务团队问答，也可作为 Coding Agent 的知识入口，但执行修改仍由具体应用授权，专著不交付真实自动发布能力。
