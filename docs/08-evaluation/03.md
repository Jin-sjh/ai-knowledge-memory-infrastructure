# 8.3 检索与上下文评测

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

检索成功是否意味着回答正确？

建立检索、上下文和答案三个层面的可观测结果。每条答案关联实际输入证据集合，才能把错误归因于未召回、未选中或未正确利用。

## 机制与细分考点

### 8.3.1 Retrieval Recall@K

Recall@K 是前 K 个唯一候选覆盖的金标准证据数除以金标准证据总数；分母为零的样本单列，不强行设零。

### 8.3.2 Context Precision / Recall

Context Precision/Recall 对最终输入的证据单元计算，长短不等时可增加 Token 权重统计，不能直接套召回候选指标。

#### 分母不同会得到不同结论

教学算例：问题需要证据 A、B，检索返回 A、C、D，则按证据单元计 precision 为 1/3，recall 为 1/2；若装配只保留 A，context precision 变为 1，recall 仍为 1/2。这个数字是手算示意，不是本项目测得的成绩。

因此需要分别保存召回列表与最终输入。回答碰巧正确也不能说明 B 被找到；答案忠实也不能说明证据足够完整。评测预先定义证据等价关系、重复片段处理和不可回答题规则，避免逐题改变评分口径。

### 8.3.3 Answer Faithfulness

Faithfulness 检查可验证的答案断言是否被实际上下文支持；模型原有知识猜对也不能算有证据支持。

### 8.3.4 Answer Correctness

Answer Correctness 对独立答案标准核对实体、条件和时点，与忠实度形成二维评测，揭示错误来源影响。

### 8.3.5 Context Utilization

Context Utilization 可通过移除关键证据、替换干扰和位置变换观察答案变化；变化相关性不能简单证明因果机制。

## 推导与工程过程

若金标准证据为 A、B、C，Top4 为 A、A、D、B，去重后覆盖 A、B，Recall=2/3；按唯一返回证据计算 precision=2/3，而若按固定槽位计算则为 2/4。两种分母含义不同，应提前声明。本仓库评分采用先去重再截 K，只报告召回与指定禁止项残留。

未列为 forbidden 的无关材料不会被脚本自动判定泄露，因此禁止项计数不是全面安全证明。正式评测应增加主体授权判定与输出文本审查。

## Atlas 案例

正确规则在候选 Top20，却因预算被裁掉，属于上下文选择失败；规则已在输入却生成单人审批，属于利用或生成失败。

## 适用条件与局限

答案忠实于错误材料仍可能事实错误，因此忠实度与正确率必须分开。
