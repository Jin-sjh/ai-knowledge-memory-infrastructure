# 8.3 检索与上下文评测

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

检索成功是否意味着回答正确？

建立检索、上下文和答案三个层面的可观测结果。每条答案关联实际输入证据集合，才能把错误归因于未召回、未选中或未正确利用。

### 8.3.1 Retrieval Recall@K

#### 仓库评分脚本实际计算了什么

设必要证据为 A、B、C，预测列表为 A、A、D、B，K=3。本仓库脚本先按对象身份去重，再取前三个，得到 A、D、B，因此覆盖两项，Recall 为 2/3。若另一个系统先取三个槽位再去重，只剩 A、D，结果会不同。比较前必须统一口径。

脚本只对 relevant 非空的问题累计召回；relevant 为空的题单独计数，不自动算作召回成功。它还检查被列为 forbidden 的对象是否进入截断后的结果。例如隔离题返回 preference@1，会增加禁止项计数。

这并不等于脚本检测了所有无关材料或泄露。未标为 forbidden 的对象不会自动判为禁止，答案文本也没有在这个函数中作语义核验。若系统最终仍在回答中泄露内容，只有候选 ID 的评分不能发现全部问题。

代码要求预测问题 ID 与金标准一一对应，重复或遗漏直接报错，避免只提交容易问题来抬高均分。具体实现见[评分函数](../../scripts/score.mjs)，正式实验应另外检查最终上下文与回答，而不是将这一个函数的输出作为综合系统成绩。

### 8.3.2 Context Precision / Recall

Context Precision/Recall 针对最终输入，而不是全部检索结果。重排、压缩和预算选择可能提高精度，也可能丢失必要证据，因此应保留召回列表与装配列表分别评分。

标注时区分必要、辅助、无关和禁止内容。若用 Token 而非证据单元作为分母，应明确口径，不让冗长重复材料虚增覆盖。

因此需要分别保存召回列表与最终输入。回答碰巧正确也不能说明 B 被找到；答案忠实也不能说明证据足够完整。评测预先定义证据等价关系、重复片段处理和不可回答题规则，避免逐题改变评分口径。

### 8.3.3 Answer Faithfulness

Faithfulness 检查答案中的陈述是否被给定材料支持。例如来源只说普通发布，答案扩大到所有发布，即使引用了原文也不忠实。

按命题拆解并核对支持关系，保留争议复核。它不等于当前事实正确：模型可能忠实引用一份过期材料，故需与版本和事实指标共同报告。

### 8.3.4 Answer Correctness

Correctness 比较答案与该任务时点的正确结论，包括必要条件、数值与拒答要求。模型可能不引用却猜中答案，也可能引用充分但用错时点。

因此答案正确、依据正确与表达符合偏好分别打分。对证据冲突题，正确行为可能是说明未决而非选定一个值，金标准必须体现这一点。

### 8.3.5 Context Utilization

上下文利用评测观察必要材料是否真正影响答案。可以加入相关但相反的旧版干扰、改变证据位置或移除关键片段，再比较输出变化。

单看答案引用次数无法证明理解。实验固定其他因素，并记录实际输入；若移除证据后仍正确，可能来自模型先验，不宜据此宣称检索没有作用于所有任务。
