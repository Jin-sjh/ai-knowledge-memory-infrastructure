# 8.3 检索与上下文评测

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

检索成功是否意味着回答正确？

建立检索、上下文和答案三个层面的可观测结果。每条答案关联实际输入证据集合，才能把错误归因于未召回、未选中或未正确利用。

### 8.3.1 Retrieval Recall@K

Recall@K 检查前 K 个检索结果找回了多少必要证据。先为问题定义相关证据集合，再计算：

~~~text
Recall@K = 前 K 个结果中命中的不同相关证据数 / 全部相关证据数
~~~

例如一个问题需要 A、B、C 三条证据，前三个结果为 A、D、B，只找回 A、B 两条，Recall@3 为 2/3。D 不相关，不增加召回；缺失的 C 不能由重复返回 A 补足。这是手算说明，不是项目效果成绩。

#### 先约定重复与不可回答题怎样处理

若原始返回为 A、A、D、B，先取三个槽位再去重得到 A、D，召回为 1/3；先去重再取三个不同结果得到 A、D、B，召回为 2/3。两种做法消耗的结果槽位不同，需要在实验前声明，不能混用。

若问题没有可用相关证据，分母为零，就不应直接套公式或默认记为满分。应单独检查该题是否正确报告证据不足，以及是否返回禁止使用的内容。

#### 本仓库脚本采用的具体约定

[评分函数](../../scripts/score.mjs)先按对象 ID 去重，再截取 K。金标准中的 relevant 表示相关证据 ID；relevant 非空的题分别计算召回，再取题目间平均；为空的题单独计数，不进入召回平均。

forbidden 列出该题明确禁止出现的 ID。例如以 u2 身份查询 u1 私有偏好时，返回 preference@1 会增加禁止项计数。未列入 forbidden 的对象不会自动被判为泄露，因此该计数不能作为完整权限证明。

脚本还要求预测题号与金标准一一对应，防止通过遗漏难题改变结果。它只检查候选 ID，没有对最终回答作语义评分；完整评测仍需检查下面的上下文指标、答案正确性和实际授权。

### 8.3.2 Context Precision / Recall

Context Precision/Recall 针对最终输入，而不是全部检索结果。重排、压缩和预算选择可能提高精度，也可能丢失必要证据，因此应保留召回列表与装配列表分别评分。

标注时区分必要、辅助、无关和禁止内容。若用 Token 而非证据单元作为分母，应明确口径，不让冗长重复材料虚增覆盖。

评测时分别保存召回列表与最终输入，检查必要证据在哪一步缺失。回答碰巧正确不证明证据已找到，答案忠实也不证明证据完整；证据等价、重复处理和不可回答题的规则都应提前确定。

### 8.3.3 Answer Faithfulness

Faithfulness 检查答案中的陈述是否被给定材料支持。例如来源只说普通发布，答案扩大到所有发布，即使引用了原文也不忠实。

按命题拆解并核对支持关系，保留争议复核。它不等于当前事实正确：模型可能忠实引用一份过期材料，故需与版本和事实指标共同报告。

### 8.3.4 Answer Correctness

Correctness 比较答案与该任务时点的正确结论，包括必要条件、数值与拒答要求。模型可能不引用却猜中答案，也可能引用充分但用错时点。

因此答案正确、依据正确与表达符合偏好分别打分。对证据冲突题，正确行为可能是说明未决而非选定一个值，金标准必须体现这一点。

### 8.3.5 Context Utilization

上下文利用评测观察必要材料是否真正影响答案。可以加入相关但相反的旧版干扰、改变证据位置或移除关键片段，再比较输出变化。

单看答案引用次数无法证明理解。实验固定其他因素，并记录实际输入；若移除证据后仍正确，可能来自模型先验，不宜据此宣称检索没有作用于所有任务。
