# 8.4 生命周期与系统正确性

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

怎样验证生命周期与恢复正确性？

把系统看成可注入事件与故障的状态机。对同一输入历史检查主记录、派生视图和最终访问结果，避免只测单个函数返回成功。

### 8.4.1 数据一致性

一致性测试把主记录、当前指针、索引及摘要放到同一事件链核对。规范更新后，各视图允许暂时落后到什么程度应预先定义，在线过滤必须遵守当前状态。

在写入、发布和确认边界注入失败，检查恢复后没有旧版复活或孤立引用。最终页面可打开不代表跨模块状态已经一致。

### 8.4.2 知识更新正确率

更新正确率不只看新内容是否存在，还要看旧版何时停止作为当前规则、历史查询是否仍可解释，以及没有变化的对象是否保持正确。

构造新增、修改、移除、权限变化及重复通知，保存前后版本。全量重建与增量方案使用同一事件集，比较正确性与恢复成本后再比较速度。

### 8.4.3 冲突识别与处理

冲突测试包括真冲突、条件不同、时间不重叠和证据不足四类，分别检查识别与处理。把所有不同值都送审会产生大量误报，全部采用最新版又会漏掉同时间矛盾。

审核结果也要检查是否绑定具体版本，以及后续回答是否采用裁决。发现冲突不等于冲突已经被安全处理。

### 8.4.4 删除传播与权限正确性

删除与权限用例以不同主体、作用域和访问方式组成矩阵。撤回 u1 偏好后，精确查询、宽前缀搜索、缓存和派生摘要都不应继续用于不允许的用途。

记录传播延迟和失败副本，同时确认 u2 与项目规则未受误删。禁止项清单只覆盖已标注风险，不构成所有安全问题均已证明不存在。

### 8.4.5 任务状态恢复正确性

恢复测试在外部动作前、远端已成功但本地未确认、检查点已提交等边界中断。重启后核对动作次数、确认状态和最终结果，而不仅是任务是否成功。

当前内存示例只能验证同进程的状态分工；跨进程耐久恢复与真实副作用需要额外实现和实验。未执行的部分明确标为待验证。

后一个实验尚未实现，也未运行。验收必须检查外部动作次数、检查点版本和最终任务状态；仅看任务最终成功，可能掩盖动作重复。内存 Store 重新创建为空的现有断言，还说明不能把同进程恢复推广为跨进程持久化。[固定版本源码](https://github.com/langchain-ai/langgraphjs/blob/959f041dfb8f6bbafa6af3ebb4bc20484a9290da/libs/checkpoint/src/store/memory.ts#L188-L219)。

故障注入要覆盖每个持久化边界：事务前、提交后消息发送前、索引写后确认前、删除屏障后副本清理前。对每个注入点记录恢复动作与最终不变量。仅随机杀进程而不核对具体边界，难以解释漏测和失败。

恢复不变量包括有效版本不重复、旧任务不复活删除信息、已确认副作用不再执行、未确认操作需查询远端。输出“任务成功”不能替代这些逐项断言。
