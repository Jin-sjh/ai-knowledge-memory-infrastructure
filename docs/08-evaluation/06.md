# 8.6 对照实验设计

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

怎样做公平的对照与消融？

冻结训练/开发/测试划分、模型、提示、数据可见范围和运行配置。各基线使用相同原始信息权限；明确预算匹配和资源不限的比较是不同实验。

## 机制与细分考点

### 8.6.1 Baseline：无外部知识与记忆

无外部信息 Baseline 只见任务问题，检验模型原有能力；避免把测试答案写进提示或开发样例。

### 8.6.2 Long Context Baseline

Long Context 输入同一可见历史，在固定预算下采用预先确定截取策略，记录因窗口被排除的证据。

### 8.6.3 RAG Baseline

RAG 使用文档检索但无长期个人记忆，固定 K、切块、模型和重排设置，开发集调参后锁定。

### 8.6.4 Memory Baseline

Memory Baseline 使用历史偏好与事件但无额外项目知识检索，以辨别个人记忆增益与组织知识增益。

### 8.6.5 Wiki / Graph Baseline

Wiki/Graph 分别设置条件，记录其离线构建信息、时间和成本，不能把两种方案的最好结果混报为一个基线。

### 8.6.6 Hybrid Architecture

Hybrid 组合知识、记忆和上下文策略，资源开销也随之报告，不能仅用质量提升掩盖预算差异。

### 8.6.7 Ablation Study：关键模块消融实验

消融一次去掉一个机制，如时态、重排或冲突检测；权限隔离不能在共享真实数据上关闭，相关实验只用合成数据。

#### 先做可解释的配对消融

参考实验固定同一来源历史与模型，仅关闭时态裁决。对“详细改简短”的测试，比较旧偏好进入上下文的比例，并复核最终答案。再单独关闭重排，观察证据覆盖；不要同时更换模型和切块后把差异归因于一个模块。

每个条件保存配置哈希、输入事件顺序、候选与上下文日志。跨用户 namespace 测试可以沿用仓库官方包示例验证存储原语，但模型实验需要独立测试集与多次运行。现有断言数量不是测试集规模，更不是框架综合得分。 [固定版本源码](https://github.com/langchain-ai/langgraphjs/blob/959f041dfb8f6bbafa6af3ebb4bc20484a9290da/libs/checkpoint/src/store/memory.ts#L188-L219)。

#### 实验条件与结果记录

下表是待执行实验的配置要求，不是效果排名。每个条件只能读取同一测试时点之前、同一授权范围内的信息。

| 条件 | 输入来源 | 固定变量 | 主要观察 |
| --- | --- | --- | --- |
| 无外部信息 | 当前问题 | 模型、生成提示 | 先验能力及猜测 |
| Long Context | 原始可见历史 | Token 预算、截断规则 | 证据遗漏和位置效应 |
| RAG | 项目文档 | 分块、K、重排 | 项目规则覆盖 |
| Memory | 用户历史 | 提取与更正策略 | 偏好与事件召回 |
| Hybrid | 文档及用户历史 | 各分支配置、总预算 | 联合正确性与成本 |

一次运行应保存 run_id、代码提交、数据哈希、条件名、模型实际版本、随机配置、逐题预测、候选和上下文标识、错误类型、耗时及调用量。模型参数不支持固定随机种子时如实记录，不把请求重试当作独立重复实验。

未执行的记录使用“未运行”，失败的记录保留失败原因；不要把空值填成零。正式报告既给整体结果，也分别报告更正、删除、跨主体隔离和不可回答题，避免总体均分掩盖少数严重错误。

## 推导与工程过程

同题配对差异可以减少问题难度差异的影响，但样本独立性仍需检查。来自同一用户或事件链的多道题通常相关，bootstrap 应按链采样而不是把每道题视为独立。重复运行处理模型随机性，不能弥补数据缺少多样性。

测试集必须在调参前冻结。若看测试失败再调 K、提示或切块，结果变成开发反馈，应准备新的保留集。公开演示 fixture 太小且答案可见，只用于验证格式和评分流程。

## Atlas 案例

相同测试问题分别运行无记忆、长上下文、RAG、Memory 和 Hybrid；按问题配对统计差异，并记录拒答和成本。

## 适用条件与局限

没有实际运行不生成分数；多次重复、置信区间和失败分析属于后续实验要求。
