# 8.6 对照实验设计

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

怎样做公平的对照与消融？

冻结训练/开发/测试划分、模型、提示、数据可见范围和运行配置。各基线使用相同原始信息权限；明确预算匹配和资源不限的比较是不同实验。

### 8.6.1 Baseline：无外部知识与记忆

无外部信息基线只给当前问题，帮助观察模型先验与猜测能力。不能把测试答案写入系统提示、示例或隐藏任务背景，否则不再是该基线。

私有规范题的正确答案即使被猜中，也应与证据充足区分。固定模型和生成设置，保存输入，确保比较的差异确实来自外部访问。

### 8.6.2 Long Context Baseline

长上下文基线读取同一授权范围与时点的原始历史，在固定预算下使用预先确定的选择和截断规则。不能人工挑出含答案的片段再称为直接阅读。

记录被排除的证据和输入顺序。资源匹配与全量输入可以分别实验，报告时说明条件，不能把不同预算的结果混作同一对照。

### 8.6.3 RAG Baseline

RAG 基线读取项目知识，不使用长期个人记忆；分块、K、重排与模型在开发阶段确定后冻结。测试记录召回与最终上下文，以解释失败。

若额外启用用户档案或为某题手动加证据，应作为新条件记录。基线的价值是稳定可比，而不是故意设置成弱方案来突出复杂架构。

### 8.6.4 Memory Baseline

Memory 基线只使用允许的用户历史与经历，不接额外项目知识检索，用来区分个性化收益与规范知识收益。形成成本与保存策略也要固定。

对测试时点之后的更正不能提前读取。手写金标准记忆可以作为单独的理想条件，但不能冒充真实提取流程，否则会隐藏形成阶段误差。

### 8.6.5 Wiki / Graph Baseline

Wiki 与 Graph 分别定义构建流程、来源可见范围、配置和成本。二者组织方式不同，不宜把各自最好结果混成一个基线。

建库若使用测试问题或答案，必须说明这是任务特定条件。正常对照应在冻结来源上构建，再使用独立测试集，避免把答案编译进知识表示。

### 8.6.6 Hybrid Architecture

Hybrid 在明确预算下组合知识、记忆及上下文策略，比较整体质量和额外资源。结果变好后，再通过消融判断哪一部分起作用。

保持同一授权与时点，不能因接更多数据源就获得本来不可见的信息。联合系统还需单独检查分支失败与冲突，平均提升不能抵消越权。

### 8.6.7 Ablation Study：关键模块消融实验

#### 用相同事件链比较，为什么还要按链划分数据

一条用户历史可能生成十道问题：询问偏好、修改后再问、撤回后再问等。若把前五道放开发集、后五道放测试集，系统可能已经通过相同事件与措辞调过规则，测试不再独立。

参考划分以用户、项目或事件链为分组，保证相关历史整体进入某一划分；测试时只暴露问题时点之前允许看到的事件。建库和记忆形成也受此限制，不能只限制最终生成提示。

消融时关闭时态处理，保持相同候选和模型，观察旧版进入上下文的变化；若同时换模型、扩大窗口和调整 K，就不能把提升归因给时态模块。对多轮随机输出，可重复运行，但重复次数不是独立用户数量。

看过测试失败再调配置后，该批样本应作为开发反馈，另留未使用的测试链。实验规程约束的是信息流与决策过程，不是仅在文件上贴 train、test 标签。

每个条件保存配置哈希、输入事件顺序、候选与上下文日志。跨用户 namespace 测试可以沿用仓库官方包示例验证存储原语，但模型实验需要独立测试集与多次运行。现有断言数量不是测试集规模，更不是框架综合得分。[固定版本源码](https://github.com/langchain-ai/langgraphjs/blob/959f041dfb8f6bbafa6af3ebb4bc20484a9290da/libs/checkpoint/src/store/memory.ts#L188-L219)。

#### 实验条件与结果记录

下表是待执行实验的配置要求，不是效果排名。每个条件只能读取同一测试时点之前、同一授权范围内的信息。

| 条件 | 输入来源 | 固定变量 | 主要观察 |
| --- | --- | --- | --- |
| 无外部信息 | 当前问题 | 模型、生成提示 | 先验能力及猜测 |
| Long Context | 原始可见历史 | Token 预算、截断规则 | 证据遗漏和位置效应 |
| RAG | 项目文档 | 分块、K、重排 | 项目规则覆盖 |
| Memory | 用户历史 | 提取与更正策略 | 偏好与事件召回 |
| Hybrid | 文档及用户历史 | 各分支配置、总预算 | 联合正确性与成本 |

一次运行应保存 run_id、代码提交、数据哈希、条件名、模型实际版本、随机配置、逐题预测、候选和上下文标识、错误类型、耗时及调用量。模型参数不支持固定随机种子时如实记录，不把请求重试当作独立重复实验。

未执行的记录使用“未运行”，失败的记录保留失败原因；不要把空值填成零。正式报告既给整体结果，也分别报告更正、删除、跨主体隔离和不可回答题，避免总体均分掩盖少数严重错误。

同题配对差异可以减少问题难度差异的影响，但样本独立性仍需检查。来自同一用户或事件链的多道题通常相关，bootstrap 应按链采样而不是把每道题视为独立。重复运行处理模型随机性，不能弥补数据缺少多样性。
