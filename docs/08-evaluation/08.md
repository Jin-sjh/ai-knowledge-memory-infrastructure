# 8.8 完整参考项目

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

如何将全书落成可验证的参考项目？

参考项目 Atlas 使用合成项目规范、偏好对话和任务日志，验证统一底座与独立策略。交付设计、数据格式和执行规程，后续实现可按同一契约替换组件。

## 机制与细分考点

### 8.8.1 需求与边界

需求包括规则问答、偏好个性化、历史查询、更正、删除和恢复；排除真实发布、模型训练及完整业务权限平台。

### 8.8.2 数据模型

使用 Source、Evidence、Item、Checkpoint 和 DerivedArtifact；合成 fixture 记录事件与金标准，权限从可信身份上下文注入。

### 8.8.3 系统架构

模块化应用配主库与可重建索引，按第六章分层；先实现确定性路径，再接模型与向量检索。

### 8.8.4 关键流程实现

依次实现采集、候选提取、策略写入、联合访问与治理任务；每步定义可核对结果，代码实现属于后续里程碑。

#### 把已存在的局部实验接到项目契约

仓库目前有两种可执行材料：formation 用预设候选检查处理与写入边界，官方 LangGraph 示例检查 Store 与 checkpoint 分工。两者验证不同对象，不能拼接成一个已经跑通的端到端知识记忆系统。集成时还缺模型提取、联合检索、权限服务及删除协调。

参考实施顺序是先将局部结果映射到 Source、Item 与 Checkpoint，再补在线访问和治理；每补一个模块，保留阶段日志并增加端到端事件链。运行入口与真实断言见[实验材料](../../examples/projects/README.md)和[形成实验](../../labs/formation/README.md)。完整系统结果仍须实际运行后填写。

### 8.8.5 评测与优化

按配套规程冻结配置、执行各基线、保存预测、评分和分析。先纠正数据及权限错误，再讨论性能优化。

### 8.8.6 架构扩展

新增 Wiki/Graph 或拆服务前，复用同一回归集证明治理与效果无倒退；扩展需新增专项数据而非只提高已有样本分数。

## 推导与工程过程

参考项目实施顺序以可观察不变量为门槛：先建立原始来源和时态版本，再完成确定性规则查询；随后加入偏好、更正与删除；最后加入检索和上下文。每阶段运行同一事件链回归，避免新增模型模块掩盖已有状态错误。

完整演示应展示 E01 到 E08 的输入、对象变化与最终访问结果，而不仅是一次聊天截图。后续公开实验时提供运行配置、预测文件和复核说明；本版只交付协议和合成样例，不以离线金标准回放冒充端到端效果。

## Atlas 案例

用规则从一人变两人、偏好从详细变简短、删除偏好、任务中断恢复的完整事件序列，对照检查状态与答案。

## 适用条件与局限

仓库没有运行中的服务；合成样本和离线评分示例不构成系统效果证明。
