# 1.4 记忆工程理论

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

什么样的持久化才算 Agent 记忆？

Agent Memory 是为未来任务管理历史信息的机制，包括选择、组织、召回与修正。MemGPT 的层次化管理是一种实现路线，不是所有记忆系统的定义。[R02]

### 1.4.1 Agent Memory 的定义

本书把 Agent 记忆理解为：主体保留的历史信息，通过明确访问机制影响后续任务。用户偏好、过往故障经历和经过验证的操作方法都可能属于记忆，但每类信息的保存和调用方式不同。

仅把聊天日志存下来只能证明历史存在。要形成可用记忆，还要决定哪些内容值得提取、怎样关联主体、何时召回、如何更正，以及何时停止使用。

### 1.4.2 短期记忆与长期记忆

短期记忆服务于当前任务连续性，例如刚选中的项目和本轮工具结果；长期记忆服务于跨任务复用，例如用户明确确认的默认偏好。分界是管理用途，不是统一规定“超过一天就是长期”。

任务结束后，可丢弃临时草稿、保留必要执行记录，再把有价值的经历提成候选。直接永久保存整段短期输入会增加隐私、噪声与更正成本，也未必改善召回。

### 1.4.3 语义、情景与程序性记忆

“生产发布需要两人”是语义层面的规则；“上次发布因角色配置失败”是情景经历；“出现该错误时检查角色映射”是程序性方法。三者分别支持事实判断、相似经历回忆和行动选择。

分类不是要求三套数据库，而是避免错误复用：一段失败经历不能直接当成普遍因果，一套操作方法必须核对环境前提，规则则要核对有效版本。

### 1.4.4 记忆形成、巩固、召回与遗忘

形成决定保存什么，巩固把分散记录整理成可复用表示，召回决定本次使用什么，遗忘限制后续使用。用户改变偏好时，新表达被保存，当前默认被重建，旧默认不再主导召回，撤回时相关派生物停止使用。

只在写入端追加一句“用户现在喜欢简短”，并不能证明后续环节已经完成。应分别观察记录、当前视图与最终上下文。

Mem0 所读添加路径先使用旧记忆辅助提取，再追加新记录。这个机制提供历史上下文，却不自动证明候选稳定、值得长期保存。对高影响偏好，本书建议将候选状态与正式档案分开；这是应用策略建议，不是对框架默认能力的描述。[固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

记忆闭环可以用两次任务说明。任务 A 中发生一次审批失败；系统保存事件、环境和结果。任务 B 中出现相似发布需求，召回该事件并提醒核验审批。如果提醒被用户确认有用，可记录使用反馈；若失败原因后来被纠正，则旧经验同时更新。这里学习发生在外部信息与策略层，不意味着模型权重已经训练。

记忆性能的关键不是让每次调用见到全部过去，而是让当前调用看到足以改变正确选择的历史，并使错误历史可退出这一过程。

### 1.4.5 Agent Memory 与传统数据库持久化的区别

数据库持久化解决记录能否可靠保存和读取；记忆工程还要决定记录怎样影响智能行为。数据库完全可以正确返回旧偏好，但如果系统没有表达更正关系，回答仍然会错。

记忆系统依赖持久化、版本和索引能力，在上面增加提取、选择和治理策略。选择数据库时看一致性与查询需求，设计记忆时还要看语义粒度和使用条件。
