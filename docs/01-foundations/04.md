# 1.4 记忆工程理论

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

什么样的持久化才算 Agent 记忆？

Agent Memory 是为未来任务管理历史信息的机制，包括选择、组织、召回与修正。MemGPT 的层次化管理是一种实现路线，不是所有记忆系统的定义。[R02]

## 机制与细分考点

### 1.4.1 Agent Memory 的定义

最小闭环是历史输入影响未来决策，并可解释影响来自哪条记录。全量日志只是记忆原料，还需要访问与修正机制。

### 1.4.2 短期记忆与长期记忆

短期与长期描述保留或访问层次，不等于具体数据库。短期会话也可持久化，长期偏好也可能很快被更正。

### 1.4.3 语义、情景与程序性记忆

语义记忆保存一般陈述，情景记忆保存经历，程序性记忆保存带前提的方法。同一次事件可产生三种派生信息。

### 1.4.4 记忆形成、巩固、召回与遗忘

形成选择保存内容，巩固整理冗余，召回选择当前有用信息，遗忘降低激活或删除。每环都可能损失关键条件。[R03]

#### 保留信息与形成可用记忆之间

用户一次说“今天赶时间”可以作为情景事件；直接提升为长期简短偏好会改变以后的所有回答。形成阶段先保留发生时间和适用任务，后续出现明确的长期表达或重复确认，再决定是否更新档案。召回时也要检查当前任务是否匹配。

Mem0 所读添加路径先使用旧记忆辅助提取，再追加新记录。这个机制提供历史上下文，却不自动证明候选稳定、值得长期保存。对高影响偏好，本书建议将候选状态与正式档案分开；这是应用策略建议，不是对框架默认能力的描述。 [固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

### 1.4.5 Agent Memory 与传统数据库持久化的区别

数据库提供事务与存取，记忆工程还需要价值选择、归属、时态和纠错。事务成功无法证明内容值得保存。

## 推导与工程过程

记忆闭环可以用两次任务说明。任务 A 中发生一次审批失败；系统保存事件、环境和结果。任务 B 中出现相似发布需求，召回该事件并提醒核验审批。如果提醒被用户确认有用，可记录使用反馈；若失败原因后来被纠正，则旧经验同时更新。这里学习发生在外部信息与策略层，不意味着模型权重已经训练。

记忆性能的关键不是让每次调用见到全部过去，而是让当前调用看到足以改变正确选择的历史，并使错误历史可退出这一过程。

## Atlas 案例

Atlas 保留用户跨会话的答复偏好，而不永久保存每个临时工具输出；当前用户明确要求详细说明时，旧偏好不能压过当前要求。

## 适用条件与局限

记忆类别是工程类比，不能据此宣称系统具有完整人类记忆或意识。
