# 1.2 核心概念体系

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

知识、记忆、状态和上下文分别是什么？

本书采用工程操作性定义：知识强调可复用陈述，记忆强调主体保留的历史，状态强调执行位置，上下文强调本次调用可见输入。分类服务于管理决策，不宣称唯一哲学定义。

## 机制与细分考点

### 1.2.1 Data、Information、Knowledge 的区别

Data 是观测符号，Information 是带语境的表达，Knowledge 是可支持判断的组织化陈述。这不是质量自动升级阶梯，错误陈述组织后仍可能错误。

### 1.2.2 Knowledge、Memory、Experience 的关系

Experience 关联事件、行动与结果，Memory 是被保留的历史信息，Knowledge 可由经验抽象或来自规范。一次成功不足以证明普遍规律。

### 1.2.3 Context 与 Memory 的区别

Context 是实际推理输入，Memory 是跨调用可管理的信息。即时工具结果可以进入上下文；未召回记忆仍存在但不影响本轮输入。

### 1.2.4 State 与 Memory 的区别

State 支持精确继续执行，Memory 支持未来选择。检查点需要版本、游标及待处理副作用，自然语言摘要不能安全替代。

### 1.2.5 Knowledge Base、Memory Store、Context Store 的区别

Knowledge Base、Memory Store、Context Store 分别管理可复用知识、主体历史与偏好、输入缓存。可以共享数据库，却需要不同保留策略。

## 推导与工程过程

判断一条信息属于哪里，可以问三个问题：它服务于哪个主体；保存它是为了恢复执行、复用事实，还是复用经验；删除它会破坏哪种能力。对于“第 3 页已同步”，若下次必须从第 4 页继续，它属于检查点；若用于分析同步失败规律，它同时是经验来源。两个用途可以关联同一个事件，但不能共享同一份可随意压缩的恢复表示。

数据模型应允许这种多用途，却避免概念循环：不能因为“保存在 Memory Store”就定义它是记忆，也不能因为“检索出来”就定义它是知识。分类根据用途和治理责任，而非组件名称。

## Atlas 案例

发布需要两人审批是项目知识；先给结论是用户偏好记忆；同步到第三页是任务状态；本轮选中的规则与偏好共同进入上下文。

## 适用条件与局限

同一信息可有多个用途，不能只按内容或保存时长分类。
