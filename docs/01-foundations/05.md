# 1.5 知识与记忆的统一理论模型

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

如何统一底座而不抹平差异？

本书提出共享对象与证据链、独立管理策略的参考模型。信息对象由内容、语义类型、出处、作用域、有效时间、验证状态和版本组成。策略依用途决定形成、访问与演进。

### 1.5.1 知识和记忆的共同基础

知识和记忆都需要稳定标识、来源、时间、归属与可见状态。规范“需要两人”和偏好“先给结论”可以共享这些管理字段，使访问层知道它们从哪里来、对谁可用、是否已被替代。

共同字段不意味着共同真值规则。规范依靠有效发布流程，偏好依靠主体表达和范围；底座应记录依据，业务策略负责解释依据。

### 1.5.2 知识和记忆的语义交叉

一段故障记忆可能包含可复用知识，一条项目规范也可能被某个 Agent 记住。两种标签可以重叠，关键是保留用途：相似经历用于提出排查线索，正式规则用于判断当前要求。

不要因为内容进入 Memory Store 就降低规范的治理要求，也不要因为经验被写进 Wiki 就把它当成普遍结论。提升为共享知识应有独立验证和授权步骤。

### 1.5.3 知识管理与记忆管理的生命周期差异

知识更新通常围绕来源修订、审核和发布；个人记忆演进还涉及主体偏好变化、情景失效与撤回。两者都需要历史，但“新版本获批”和“用户今天临时要求”不能使用同一种替代规则。

统一生命周期接口可以提供创建、失效和删除事件，具体何时生效仍由对象策略决定。否则临时偏好可能被误发布为长期默认，草稿规范也可能被当作现行知识。

### 1.5.4 共享数据模型与独立处理策略

共享模型可以让规则和偏好使用同一套来源引用与权限检查，独立策略则决定各自写入和读取方式。规则更改要查发布依据，偏好更改要核对主体、范围与长期意图。

如果只提供一个无条件覆盖的 save 接口，调用方就无法表达这些差异。可以统一底层存储协议，同时在服务层保留“提交规范候选”“确认偏好”等不同操作。

可将底座理解为共同提供标识、来源关联和生命周期钩子，业务层分别管理规范与个人历史。LlamaIndex 的文档哈希更新和 Mem0 的候选追加展示了不同更新单位；接入统一接口时应保留各自语义，而不是都映射成不带前提的 save。[固定版本源码](https://github.com/run-llama/llama_index/blob/baeabbfe26241a6916e13e2a8c8156a02e0602cd/llama-index-core/llama_index/core/ingestion/pipeline.py#L469-L507)。

统一对象不代表统一决策函数。可将知识写入策略表示为 Pk(source,review,domain)，记忆写入表示为 Pm(subject,intent,utility)。二者共用对象标识、证据和授权接口，却可以对同一候选作不同决定：会议聊天中的临时设想可留情景记忆，但尚不足以成为正式项目规范。

这一设计的可推翻条件是共享字段和治理造成的复杂度高于互操作收益。若某类程序性记忆需要独立执行验证与事务语义，应在共享出处与权限契约之上独立建模，而不是强塞进通用文本字段。

### 1.5.5 Unified Knowledge & Memory Infrastructure 的定义

统一基础设施指让知识、记忆与相关状态在共同的标识、来源、访问和治理约定下协作，不是把所有内容塞进同一个向量集合。一次回答可以组合规则、偏好与工具状态，但各自仍有独立责任。

验收统一能力时，检查规范撤回能否使摘要失效，偏好删除能否阻止缓存继续使用，检查点恢复是否仍读取当前授权范围。仅共用数据库还没有证明这些能力。
