# 1.5 知识与记忆的统一理论模型

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

如何统一底座而不抹平差异？

本书提出共享对象与证据链、独立管理策略的参考模型。信息对象由内容、语义类型、出处、作用域、有效时间、验证状态和版本组成。策略依用途决定形成、访问与演进。

## 机制与细分考点

### 1.5.1 知识和记忆的共同基础

共同基础是可标识的信息、出处、时间、作用域和约束。共享字段使来源审计与删除传播可跨知识和记忆执行。

### 1.5.2 知识和记忆的语义交叉

用户使用 Python 既可视作个人事实，也可用于个性化记忆。一个对象可关联多个用途视图，无需复制不一致的文本。

### 1.5.3 知识管理与记忆管理的生命周期差异

组织知识围绕规范版本与审核演进，个人记忆围绕交互与更正演进。两者需要证据，但证据适格标准不同。

### 1.5.4 共享数据模型与独立处理策略

共享结构解决互操作，独立策略决定自动写入、有效期和召回范围。策略版本应进入审计，以解释历史行为。

#### 统一底座为何仍需独立策略

同一条“审批需两人”可以来自项目规范，也可以来自用户回忆。共享 Source、时间与权限字段有助于联合访问，但前者应按规范版本发布，后者应保留“用户曾如此陈述”的归属。统一字段不能抹去两者的可信依据。

可将底座理解为共同提供标识、来源关联和生命周期钩子，业务层分别管理规范与个人历史。LlamaIndex 的文档哈希更新和 Mem0 的候选追加展示了不同更新单位；接入统一接口时应保留各自语义，而不是都映射成不带前提的 save。 [固定版本源码](https://github.com/run-llama/llama_index/blob/baeabbfe26241a6916e13e2a8c8156a02e0602cd/llama-index-core/llama_index/core/ingestion/pipeline.py#L469-L507)。

### 1.5.5 Unified Knowledge & Memory Infrastructure 的定义

统一基础设施提供来源管理、信息形成、存储、检索、上下文组装和治理；规划、业务执行与模型训练处于边界之外。

## 推导与工程过程

统一对象不代表统一决策函数。可将知识写入策略表示为 Pk(source,review,domain)，记忆写入表示为 Pm(subject,intent,utility)。二者共用对象标识、证据和授权接口，却可以对同一候选作不同决定：会议聊天中的临时设想可留情景记忆，但尚不足以成为正式项目规范。

这一设计的可推翻条件是共享字段和治理造成的复杂度高于互操作收益。若某类程序性记忆需要独立执行验证与事务语义，应在共享出处与权限契约之上独立建模，而不是强塞进通用文本字段。

## Atlas 案例

发布规则和用户偏好都关联来源和版本；前者跟随项目规范，后者跟随本人陈述。共享证据索引不意味着共享权威性判定。
