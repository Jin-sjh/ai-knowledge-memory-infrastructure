# 6.5 模块通信与接口设计

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

接口如何表达版本与部分失败？

采用版本化 JSON 参考契约，身份由认证层注入，客户端请求不能自行声明跨租户权限。写入返回主记录版本，异步任务返回独立状态。

## 机制与细分考点

### 6.5.1 数据读写接口

读写接口区分 create、revise 和 delete，支持幂等键与预期版本。读取历史版本仍按当前授权检查。

### 6.5.2 Search / Retrieve API

Search 返回候选与检索分数，Retrieve 返回已过滤证据与用途说明；API 明确区分排名分与验证状态。

### 6.5.3 Memory API

Memory API 支持按主体访问、纠错和遗忘请求，不能让客户端借写入 scope 字段获得更广权限。

### 6.5.4 Context API

Context API 接受任务、时间与 Token 预算，返回来源清单、压缩内容和不足项；预算不足时明确裁剪策略。

### 6.5.5 事件驱动更新与异步任务

事件包含 event_id、对象版本与模式版本，消费者幂等；任务状态区分受理、处理中、部分失败、完成。

### 6.5.6 Schema、错误处理和版本契约

Schema 负责形状，服务负责语义与权限；错误区分无效输入、冲突、不可见、依赖不可用和限流，版本升级需兼容策略。

#### 契约应暴露部分失败

参考写入响应可区分 accepted、persisted、indexed 与 rejected，并为每个候选返回稳定标识和错误类型。请求成功接收但索引未完成时，调用者应知道当前是否可检索；批量部分失败时只重试未确认项，避免重复记录。

Mem0 所读实现对模型调用异常和解析为空采用不同处理路径。适配公共 API 时应保留这种差异：供应方不可用可以重试，候选确实为空可以正常结束，解析失败则需要诊断。将三者都转换成空数组会隐藏质量问题。 [固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

#### 一次异步写入的参考契约

以下字段是用于解释职责的接口草案，不是已上线 API。实际结构仍以[API 契约](../appendices/api-contract.md)为入口。

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| request_id | req-42 | 跟踪请求，不等同对象身份 |
| candidate_id | pref-u1-atlas-3 | 稳定识别本次候选 |
| expected_version | 2 | 并发前提，过期时返回冲突 |
| persisted_version | 3 | 主记录已提交的版本 |
| index_state | pending | 检索索引尚未追平 |
| retryable | false | 是否允许原请求安全重试 |

若主库已提交而索引超时，应返回已提交版本及待索引状态；调用者可以按 ID 读取，后台重试索引。若返回笼统失败，客户端可能再次提取并生成新候选，导致重复。请求级幂等与候选级身份需要同时设计。

## 推导与工程过程

异步 API 的受理结果与完成结果分开建模。写主记录成功可返回对象版本与 indexing_job_id；客户端看到 201 只能确信主记录已提交，不能假设向量搜索立刻可见。删除接口则要求在线屏障先建立，再返回 202，后续任务负责清理。

错误契约应让调用方能作正确选择：409 先读新版本，429 按退避重试，证据不足补充来源，权限不可见不能通过换检索路径绕过。把所有失败都映射成“再试一次”会制造重复副作用。

## Atlas 案例

偏好更正携带 expected_version；版本不符返回冲突。Context 请求返回证据及 missing，不把部分成功包装成完整答案。

## 适用条件与局限
