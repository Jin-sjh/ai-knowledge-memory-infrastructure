# 6.6 多租户与 Agent 集成

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

多租户与 Agent 运行时如何集成？

将身份、作用域与运行 ID 贯穿接口和存储。共享通过显式策略建立，不能依靠同一模型、同一向量空间或同一 Agent 名称推断可见性。

## 机制与细分考点

### 6.6.1 User / Project / Organization Scope

User、Project、Organization Scope 由可信授权上下文约束；项目归属变化后重新检查对象权限，不能仅相信旧标签。

### 6.6.2 多 Agent 共享知识

多 Agent 共享知识需要共同授权域和版本约定，Agent 写入的总结仍经过普通候选验证流程。

### 6.6.3 独立记忆与共享记忆

独立记忆与共享记忆通过策略区分；把个人经验提升为团队知识需去除不必要个人信息并重新审核。

### 6.6.4 Agent Runtime 与 Workflow

Runtime/Workflow 调用知识与记忆接口，运行步骤和工具执行保留在运行模块；控制指令与来源文本严格分区。

### 6.6.5 任务状态持久化与恢复

任务恢复读取检查点和副作用账本，先核对目标状态再继续。若远端操作已成功但本地未确认，不能直接重复执行。

### 6.6.6 权限隔离、安全与审计

服务层过滤配合数据库约束与审计；跨租户测试需覆盖索引、缓存、摘要和错误信息，防止旁路泄露。

## 推导与工程过程

多租户隔离检查的最小闭包包含主库行、向量元数据、图路径、缓存键、摘要依赖、导出文件和错误消息。即使主库 RLS 正确，若上下文缓存只按 query 缓存，两个用户相同问题仍可能共享私有结果。[R08]

共享派生物不直接拥有比输入更宽的权限。最保守策略是要求读取者可访问全部依赖；若要生成不同权限视图，需要重新构建并证明输出不含隐藏依赖信息，不能只删掉来源标签。

## Atlas 案例

u1 允许使用个人偏好，但 u2 的回答不能召回该偏好。两个 Agent 可共享项目手册，却分别拥有私有任务状态。

## 适用条件与局限

数据库行级安全可作为纵深防护，仍需检查服务角色、表所有者与绕过权限。[R08]
