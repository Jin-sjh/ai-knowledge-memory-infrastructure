# 6.4 系统核心数据流

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

核心数据流在哪些点交接？

将写入与访问分为独立流水线，用版本化事件连接演进任务。每个阶段显式说明输入、输出、失败状态与可重试条件。

## 机制与细分考点

### 6.4.1 Knowledge Ingestion Pipeline

Knowledge Ingestion 接收来源快照，解析、提取、验证后提交知识候选或有效版本，并记录来源依赖。

### 6.4.2 Memory Formation Pipeline

Memory Formation 接收交互与轨迹，识别主体、用途和价值，授权后保存候选或后继版本；临时状态转给运行模块。

### 6.4.3 Unified Retrieval Pipeline

Unified Retrieval 接收查询与可信身份上下文，召回多路候选并回查主记录，返回可见、有效的证据集合。

### 6.4.4 Context Construction Pipeline

Context Construction 根据任务和预算选择、压缩、组装，输出上下文清单及缺失项；它不能偷偷创建长期记忆。

### 6.4.5 Knowledge / Memory Evolution Pipeline

Evolution 消费变更事件，执行冲突检查、巩固、失效与重建。旧输入任务在发布前做版本核对，失败进入可观察队列。

#### 更新事件怎样穿过模块

参考事件携带 source_id、source_version、event_id 与目标 generation。消费者按事件标识幂等处理，生成新派生物后校验依赖版本仍有效，再发布。若处理期间又收到 v3，迟到的 v2 结果不能覆盖当前版本。

Mem0 的批量插入及失败回退表明底层写入可能部分成功。跨模块编排应记录每项对象的结果，并以补偿或重试恢复；不能把函数返回当作来源、历史、索引和实体关联全部原子提交的证明。 [固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

## 推导与工程过程

一条更正事件应包含被更正逻辑对象、新内容版本和明确的原因，不携带对整个存储的任意执行指令。消费者只处理其负责的派生物，幂等检查当前状态。由此即使消息重复或乱序，也不会让旧派生任务覆盖更正。

读取路径不要等待所有异步任务无限完成。可返回主记录证据、降级为精确查询或清楚说明暂缺某视图；降级也必须执行同样的授权、有效期和冲突约束。

## Atlas 案例

规则写入完成后产生索引任务；回答时如果索引尚未追上，可回查主记录或明确返回暂不可用，而不是宣称所有索引已同步。

## 适用条件与局限

一致性策略按用途选择，不能把最终一致性当作忽略即时撤权的理由。
