# 7.5 工程实现原理

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

哪些工程细节决定可靠性？

把版本、幂等、依赖与可观察性贯穿实现。算法效果与运行正确性分别验证，不能因模型输出看起来合理就跳过一致性处理。

## 机制与细分考点

### 7.5.1 Schema 与数据访问层

Schema 校验放在边界，访问层统一身份过滤与版本比较。禁止业务分支直接写索引跳过主记录。

### 7.5.2 文档处理及索引构建

解析和索引任务保存输入哈希、解析器和模型版本；支持批处理、恢复与隔离失败，不因一个坏文档阻塞整批。

### 7.5.3 LLM Structured Extraction

Structured Extraction 分离提示版本、模型配置与验证规则；保存失败原因，重试不能不断放松约束直到输出通过。

### 7.5.4 检索、融合与重排序

多路检索先标准化候选 ID，再融合与去重，统一回查权限和时态；重排只作用于合法候选。

### 7.5.5 增量更新与依赖传播

变更事件按依赖传播失效，构建前后核对输入版本；高扇出任务分批且可恢复，避免更新风暴。

### 7.5.6 并发、幂等与一致性

预期版本防并发覆盖，幂等键防重复，outbox 连接事务和消息。不要假设消息只投递一次。

### 7.5.7 缓存、性能及成本优化

缓存键包含主体权限版本、对象版本、查询与模型配置；批量嵌入与复用降成本，但不可跨授权域错误共享。

### 7.5.8 可观测性与故障恢复

追踪采集、提取、索引、检索与组装延迟，关联 trace_id；故障恢复检查重试积压、孤立索引和删除任务，而非只看在线接口。

## 推导与工程过程

缓存失效可用版本键替代到处主动删缓存：键包含 tenant、授权版本、查询、数据版本和模型配置，撤权后旧键不再命中。但旧缓存仍需按保留策略清理，且日志和导出不能因为键失效就算删除完成。

可观察性要覆盖信息链：来源采集延迟、提取拒绝率、索引落后版本、最终过滤比例、上下文裁剪和答案引用。高过滤比例可能意味着检索规划错误；只看接口成功率会掩盖质量退化。

## Atlas 案例

一次提取任务重试后应只产生一个有效版本；更新后的旧索引构建任务完成时，应被版本检查阻止发布。
