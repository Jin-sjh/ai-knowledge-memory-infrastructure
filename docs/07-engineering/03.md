# 7.3 记忆实现技术

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

记忆系统从哪里开始实现？

先实现主体、有效时间、来源、更正与精确读取，再加入语义召回。没有治理的向量集合无法可靠回答哪条偏好当前有效。

### 7.3.1 原生数据库记忆实现

原生记忆实现可以从用户、作用域、属性和当前值表开始，用事件日志保留必要变化。对明确偏好，按键读取比向量搜索更容易定义当前状态。

需要补齐版本检查、撤回与缓存失效；一张键值表不会自动具备记忆提取与语义治理。但业务较小且条件明确时，不必为此先接复杂框架。

#### LangGraph：用官方 Store 读写一条偏好

示例先用官方 Store 写入偏好，再由一个图节点读取。下面是本书编写的示例代码节选：

~~~js
const store = new InMemoryStore();
await store.put(
  ["users", "u1", "preferences"],
  "answer_style",
  { style: "详细解释" }
);
~~~

之后同一 namespace/key 写入“先给简短结论”。在所核验的 Node.js 实现中，同键写入直接替换 value 并更新时间，并不自动建立本书实验那样的内容版本链。[Store 实现](https://github.com/langchain-ai/langgraphjs/blob/959f041dfb8f6bbafa6af3ebb4bc20484a9290da/libs/checkpoint/src/store/memory.ts#L188-L219)

何时认为用户形成新偏好、何时调用 put，由应用决定。Store 不会仅因收到自然语言消息而自行提取或更正记忆。

同一键更新后，u1 的记录数仍是 1，说明这是覆盖，不是自动版本管理。新建一个 InMemoryStore 后读不到旧数据，说明这些实例不共享持久化后端；进程级持久化需要数据库存储实现。

本例未配置 embedding，因此不验证语义检索。它回答的是更基础的问题：偏好放哪里、会话状态放哪里，以及二者怎样在实际框架中组合。

Python LangGraph 与 Node.js LangGraph 使用相关概念，但本节源码链接、依赖锁与运行记录均针对 Node.js 发布版本，不把跨语言实现当作逐行一致。

### 7.3.2 Profile / Episodic / Procedural Store

Profile 保存当前稳定属性，Episodic 保存具体经历，Procedural 保存带前提的方法。一次事故可成为经历，并产生方法候选，但不应直接覆盖用户档案或自动成为通用策略。

可共用底层数据库，用不同类型和接口表达更新责任。读取时按用途组合，避免相似故障记录与当前偏好竞争同一个检索排名。

偏好当前视图可由事件链投影：按主体和属性读取候选，过滤删除与权限，按有效期选择当前明确版本；程序性方法则先匹配环境前提。它们都不需要先通过向量相似度才能取得正确记录。向量主要用于不确定措辞和类似经历发现。

框架接入应通过适配器，把本书对象 ID、来源与删除任务映射到框架能力。若不能保留这些字段，应先评估差距而非在接入后才发现无法导出或纠错。

### 7.3.3 基于向量检索的记忆系统

向量记忆便于查找“类似的故障”或措辞不同的历史，却不天然给出唯一当前值。新旧偏好都与当前用户相关，单靠相似度可能选错。

将语义搜索用于候选发现，再做时间、范围和替代过滤；明确属性可走精确档案。索引结果与主对象绑定，删除和更正才有稳定目标。

### 7.3.4 Memory Framework

接入框架前沿一次写入追踪输入、提示、解析、存储和返回，核对 add 究竟表示直接保存、提取后追加还是更新。接口名和宣传术语不足以判断实际策略。

把自身的来源、权限、删除与更正契约映射到固定版本实现；缺少的能力由适配层补充或限制使用。升级后重跑同一事件链，不能默认接口未变就语义未变。

Mem0 源码仍存在描述 ADD、UPDATE、DELETE、NONE 的旧提示，但所读同步默认添加路径采用追加提取。能力判断必须以实际调用点为依据。若业务要求自动更正当前档案，需要另行验证，不能只因找到某个提示常量就勾选支持。[固定版本源码](https://github.com/mem0ai/mem0/blob/f1791daa86d469249c9b002f62644d58a1eb96a0/mem0/memory/main.py#L918-L1098)。

### 7.3.5 Agent Runtime 集成

Runtime 集成时显式传递用户、项目、运行和请求身份。运行节点按用途读取知识与记忆，写入通过受控策略，不把所有中间草稿当长期经验。

工具动作与记忆更新可能分别成功，记录各自确认状态。恢复后先核对副作用与当前权限，不能只恢复聊天文本就继续执行。
