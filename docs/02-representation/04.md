# 2.4 知识与记忆的表示形式

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。资料核验日期：2026-11-13。

## 要解决的问题

原文、Claim、Wiki、图谱与向量如何协作？

原始来源支持复核，Claim 提供可定位陈述，Wiki 与图谱组织信息，索引加速访问。它们形成派生依赖图，来源改变时可定位重建范围。

### 2.4.1 原始文档与事件日志

原文和事件日志是重新提取、纠错与审计的基础。摘要会省略内容，而被省略的条件可能在以后成为关键，因此不能只保存摘要。

记录来源快照、采集时间与权限，再从该快照生成派生物。可变网页地址可以帮助发现更新，却不能独立承担历史复现。

### 2.4.2 结构化记录与 JSON

JSON 能让人数、状态和时间被程序检查，例如人数为正整数、结束晚于开始。[R12]结构有效并不证明模型正确理解了“两名不同审批者”。

保留原文与结构字段的对应关系，校验后继续检查证据和业务约束。解析成功只能作为进入后续处理的条件之一。

例如记录包含 subject=u1、scope=Atlas、value=brief、source=e2。结构检查可以确认字段存在、类型正确；它不能从 brief 推出原文的“追问时展开”仍被保留。若需要这一条件，应增加明确字段或保留完整陈述，而不是假设 JSON 比自然语言天然更精确。迁移旧记录时也要区分字段缺失与明确的空值，避免把未记录的范围解释成全局。

### 2.4.3 原子知识与 Claim

Claim 是可独立核验的命题候选。拆分“普通发布需两人，紧急发布另有流程”时，要保留各自条件与关联，不能只留下“发布需两人”。

原子化是为了独立更新和验证，并非越短越好。片段失去限定条件后无法独立解释，就需要补上下文或调整粒度。

### 2.4.4 Chunk 与文本片段

#### 表格的一行为什么不能脱离表头

假设章节标题是“普通生产发布”，表头是“场景｜审批人数｜角色限制”，某行是“默认流程｜2｜提交人不得审批”。单独存储“默认流程 2 提交人不得审批”，检索虽可能命中，却无法知道 2 是人数、次数还是天数。

一种参考块保留标题路径、表头、完整行和来源定位；提取 Claim 时再将场景继承为普通生产发布，将数值解释为至少或恰好还要回查规范措辞。如果相邻备注写着紧急例外，也应保留可访问关联，不能靠模型从孤立数字猜出规则。

这里存在三个独立单位：Chunk 是处理边界，Claim 是待核验命题，向量是候选发现表示。重新分块可以改变 Chunk 和向量身份，但不应悄悄改变已经批准的规则身份。LlamaIndex 的来源与邻接关系提供节点级联系；命题身份和审核仍需应用建模，详见[预处理分析](../03-formation/02.md)。

LlamaIndex 的节点处理提供来源与邻接关系，但生成节点本身不意味着完成命题验证。选择 Chunk 模型适合保留原文和快速检索；需要独立审核、冲突管理时，再增加 Claim 层。两者是不同管理粒度，并非质量高低的自动排序。[R17][固定版本源码](https://github.com/run-llama/llama_index/blob/baeabbfe26241a6916e13e2a8c8156a02e0602cd/llama-index-core/llama_index/core/ingestion/pipeline.py#L469-L507)。

### 2.4.5 Wiki 与主题知识页面

Wiki 将分散来源整理成主题解释，便于概览，但整理过程包含归纳和省略。页面需要知道结论依赖哪些来源，否则原文更新后仍可能保留完整却过时的解释。

参考设计按依赖重编译相关部分，区分人工内容和生成内容，再核对引用与条件。Wiki 的阅读便利不等于原始证据可以丢弃。

### 2.4.6 Knowledge Graph

图适合显式表示实体关系，例如服务依赖组件、人员承担角色。路径查询依赖边的方向、类型及有效期；一条“相关”边不能推出因果或权限。

抽取后先核对实体消歧和边的含义。错误关系会沿路径传播，因此图结构完整并不代表知识正确。

设图中 A 服务依赖 B，B 依赖数据库 C。查询 C 升级的影响可沿反向依赖找 B、A，再取得每条边的版本和来源；这只能确定需要核对的范围，不能保证三者都会故障。若 B 在新版本已改为依赖 D，旧的 B→C 必须退出当前遍历，历史查询才保留。图查询因此仍需要时态与来源，不是把文本换成边后就省掉治理。

### 2.4.7 Embedding 与向量表示

Embedding 帮助找出措辞不同但相关的内容，不直接决定业务真值、现行版本或权限。旧规范与新问题也可能高度相似，所以向量命中只是候选。

后续还要检查来源和状态。模型更换时评估空间兼容与重建需求，不能默认新旧向量可以直接混合比较。

派生链至少需要两种关系：表达支持关系与构建依赖关系。证据支持某 Claim 是语义关系；某向量由某段文本生成是构建关系。删除传播主要沿构建依赖与受影响证据传播，事实验证则核对语义支持。把两者统称为引用会让“为什么存在”和“为什么可信”无法区分。

向量、图和 Wiki 都可能丢失条件。图边可以增加 qualifiers，主题页可以保留例外段落，Chunk 可以携带父标题。应为每种表示设计从原文到表示的损失检查，而非假设结构化一定比文本完整。
