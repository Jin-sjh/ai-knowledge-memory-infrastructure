# 2.5 统一数据模型

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

统一模型如何保持可验证性？

参考模型分为 Source、Evidence、InformationItem、Checkpoint 和 DerivedArtifact，通过稳定 ID 与不可变版本连接。索引持有主记录引用，不承担事实真值的最终责任。

### 2.5.1 Source / Evidence Model

Source 保存输入快照，Evidence 指向其中作为依据的部分。一条规则可引用正文与例外表两处证据，多条规则也可共享来源。

引用应绑定版本。原位置仍存在但措辞改变时，旧审核不能自动沿用，需重新核对命题是否仍被支持。

### 2.5.2 Information Item Model

InformationItem 是可独立管理的内容对象，包含类型、归属、条件、来源和状态。规则与偏好可以共用结构，但各自写入与生效依据不同。

内容修订产生新版本，使旧回答仍能定位当时文本；索引位置则可随重建变化。业务身份不能由向量条目的物理位置决定。

版本引用使用逻辑 ID 与版本二元组，例如 rule@2。对象 ID 回答“是哪条规则”，版本回答“是哪次内容”。当前指针可以变化，但证据和派生依赖应引用具体版本，使一次回答能够复现其输入。只保存 latest 链接会使过去答案在来源更新后无法解释。

本书采用内容修订产生新版本、治理状态可变的最小模型；若需要不可篡改审计，应把治理变化也写入独立追加账本。别把示例中的 status 字段误读为已经满足审计防篡改要求。

### 2.5.3 Memory & Knowledge Metadata

共同字段支持联合访问，如来源、时间和权限；专有字段表达独立策略，如偏好触发范围、规范批准与生效依据。

字段扩展应说明默认含义和迁移方式。新增作用域后，历史空值不能直接解释为全局共享，否则结构升级会意外扩大可见性。

### 2.5.4 State / Checkpoint Model

检查点应保留运行身份、位置、输入版本和待确认副作用。例如“页 3 已完成，页 4 远端写入未确认”才能指导恢复；“同步进行中”不够。

重启后先核对远端结果或幂等键，再决定重试。检查点保存成功不等于所有外部动作恰好执行一次。

### 2.5.5 Derived View / Index Model

派生物需要绑定输入版本和构建配置。例如索引代际 12 来自手册 v2 与分块配置 c3，来源撤权或配置更改时才能定位受影响结果。

命中项回查当前状态负责即时阻止过期返回，后台清理负责移除副本，两者分别承担在线正确性与存储治理。

LlamaIndex 的处理缓存将节点内容与转换配置纳入键的计算，体现了“结果依赖输入及处理方式”的原则。但应用自己的权限、模型别名或外部配置未必都进入该键；这些依赖必须单独登记，不能认为框架缓存天然覆盖业务的全部失效条件。[固定版本源码](https://github.com/run-llama/llama_index/blob/baeabbfe26241a6916e13e2a8c8156a02e0602cd/llama-index-core/llama_index/core/ingestion/pipeline.py#L58-L113)。

### 2.5.6 信息实体间的关联模型

supports、supersedes、derived_from 分别表示证据支持、版本替代和派生依赖。若统一成无方向连线，就不知道该沿哪条边删除、查历史或解释答案。

两端绑定具体对象版本。这样来源更新只触发相关派生物失效，不会让旧回答的引用悄悄指向新版。

### 2.5.7 数据完整性与约束条件

完整性分为结构、跨对象约束和领域语义。外键证明来源存在，不证明支持 Claim；合法有效期不证明规范已批准；跨租户引用即使 ID 存在也可能不允许。

失败应说明是哪一层：修复字段、核对权限或补充业务依据。仅返回“验证失败”会使调用者无法选择正确处理方式。
