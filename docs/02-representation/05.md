# 2.5 统一数据模型

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

统一模型如何保持可验证性？

参考模型分为 Source、Evidence、InformationItem、Checkpoint 和 DerivedArtifact，通过稳定 ID 与不可变版本连接。索引持有主记录引用，不承担事实真值的最终责任。

## 机制与细分考点

### 2.5.1 Source / Evidence Model

Source 保存输入、哈希和权限版本；Evidence 保存来源版本及定位。一个 Claim 可由多个证据支持，单条证据也可支持多个 Claim。

### 2.5.2 Information Item Model

InformationItem 保存内容、类型、用途、作用域、有效期和验证状态。内容更新产生新版本，治理事件改变可见状态。

### 2.5.3 Memory & Knowledge Metadata

知识和记忆共用时间、出处和权限字段；记忆增加主体或触发条件，知识增加领域和审核。扩展字段需版本化。

### 2.5.4 State / Checkpoint Model

Checkpoint 保存运行 ID、步骤位置与待执行副作用。恢复前核对副作用是否已经完成，避免重复发送或写入。

### 2.5.5 Derived View / Index Model

DerivedArtifact 保存输入版本、构建器版本和哈希。来源撤权后，在线检查应阻止旧派生内容返回，不能只等后台清理。

### 2.5.6 信息实体间的关联模型

关联区分 supports、contradicts、supersedes、derived_from 和 about。没有方向和类型的关联无法可靠支撑冲突与删除传播。

### 2.5.7 数据完整性与约束条件

完整性约束包括来源存在、版本不回退、时间区间合法和跨租户关联受限。外键检查存在性，不能证明内容真实性。

## 推导与工程过程

版本引用使用逻辑 ID 与版本二元组，例如 rule@2。对象 ID 回答“是哪条规则”，版本回答“是哪次内容”。当前指针可以变化，但证据和派生依赖应引用具体版本，使一次回答能够复现其输入。只保存 latest 链接会使过去答案在来源更新后无法解释。

本书采用内容修订产生新版本、治理状态可变的最小模型；若需要不可篡改审计，应把治理变化也写入独立追加账本。别把示例中的 status 字段误读为已经满足审计防篡改要求。

配套 Schema 验证结构；证据是否支持断言、跨租户关联是否允许仍需服务层检查。
