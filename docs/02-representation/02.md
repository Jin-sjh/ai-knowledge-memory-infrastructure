## 要解决的问题

记忆层次与内容为何要分开？

使用保留层次、内容性质和作用域三个正交轴。长期可以保存一次事件，工作集也可以包含一般事实；标签不决定物理部署。

## 机制与细分考点

### 2.2.1 Working Memory

Working Memory 是当前任务直接操作的集合，受上下文预算限制。任务结束可丢弃，但恢复字段应进入检查点。

### 2.2.2 Short-term Memory

Short-term Memory 支持近期连续性，应规定轮数、时间或事件边界，避免名义短期实际无限累积。

### 2.2.3 Long-term Memory

Long-term Memory 面向跨任务复用，写入门槛较高，需要可查看、纠错和删除，不能仅靠时间衰减。

### 2.2.4 Semantic Memory

Semantic Memory 保存一般陈述，如项目约定和用户偏好，但仍应保留历史来源与适用范围。

### 2.2.5 Episodic Memory

Episodic Memory 保存单次经历及先后关系。查询某次故障时，事件时间可能比语义相似度更重要。

### 2.2.6 Procedural Memory

Procedural Memory 保存方法与条件，步骤本身不授予执行权限。执行前仍需业务授权和环境检查。

#### 程序性记忆需要可执行前提

“发布前运行检查”是程序性内容，却还缺检查命令、工作目录、成功条件和失败处理。把一次工具调用原样复用到另一个仓库，可能在错误环境执行。保存程序时至少保留适用项目、依赖版本、步骤及验证方式，执行前重新核对。

Letta Code 区分核心记忆与延后读取的深层文件，过程资料还有独立路由。它提示我们：长期保存不代表每次都加载，保存操作经验也不等于允许自动执行。文件组织的具体读取路径见[上下文路由](../05-retrieval-context/04.md)。 [固定版本源码](https://github.com/letta-ai/letta-code/blob/bd31b0a72dfad1ba14fc3a82f47da6a2b606330d/src/backend/local/system-prompt-compilation.ts#L65-L198)。

### 2.2.7 用户记忆、项目记忆与 Agent 记忆

用户、项目与 Agent 记忆按归属划分。Agent 经验扩展为项目共享知识，应经过独立共享和审核流程。

## 推导与工程过程

三轴分类可以形成组合键，但不应变成组合爆炸的枚举表。例如 scope=user/u1，retention=long_term，content=episodic 表示长期保存的用户事件；scope=project/atlas，retention=working，content=semantic 则可表示本次任务选中的项目事实。访问层按不同轴过滤，无需为每个组合建立独立服务。

保留层次的转换也要有策略：短期摘要晋升长期记忆时重新判断价值与授权，而不是达到某个存活天数后自动升级。长期记录退出活跃索引也不一定等于删除原始事件。
