# 2.2 记忆的结构与分类

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。资料核验日期：2026-11-13。

## 要解决的问题

记忆层次与内容为何要分开？

使用保留层次、内容性质和作用域三个正交轴。长期可以保存一次事件，工作集也可以包含一般事实；标签不决定物理部署。

### 2.2.1 Working Memory

工作记忆是本次推理正在使用的问题、证据和中间结果，通常受输入预算限制。回答审批问题时，当前规则和审批状态比几周前的闲聊更应进入工作上下文。

任务进度不应只留在这里。压缩或换轮后丢失精确游标，会导致恢复失败，因此重要状态需独立保存。

### 2.2.2 Short-term Memory

短期记忆保持当前任务连续性，例如刚确认的项目 ID、当前工具结果及尚未完成的比较。切换项目时，应清除或重新绑定这些条件，避免沿用旧项目参数。

它也可以落盘用于恢复；短期与长期的区别主要是是否应跨任务成为默认依据，而不只是是否持久化。

### 2.2.3 Long-term Memory

长期记忆保存跨任务有复用价值的信息，如明确偏好和已验证经验。进入长期层之前，核对主体、范围、价值和更正方式；重复出现并不自动意味着值得永久保存。

长期记录仍会因项目变化、用户撤回或环境升级失效。需要保留替代关系或重新确认条件，不能把长期等同于永远正确。

### 2.2.4 Semantic Memory

语义记忆以可复用陈述组织内容，例如术语定义与稳定配置惯例，使用时不必回放完整经历，但仍要有来源。

从日志提取“端口为 8080”时，应限定服务、环境和版本。部署变更后需要更新，否则一条结构正确的旧陈述仍会误导工具操作。

### 2.2.5 Episodic Memory

情景记忆保留一次经历的背景、行动顺序和结果。当前故障与历史报错相似时，可以召回作为排查线索，再比较依赖、输入与环境。

如果只保留“当时重启解决了”，就无法知道本次是否适用。情景细节的价值是支持比较，不是让 Agent 自动重复历史动作。

### 2.2.6 Procedural Memory

程序性记忆保存可复用方法，如某项目的测试、构建和验证步骤。方法需要环境前提和成功判据；孤立命令列表不能支持可靠复用。

升级后可以重新验证或标记过期。核心摘要与按需读取能减少上下文占用，但不能替代执行前的条件与权限核对。

Letta Code 区分核心记忆与延后读取的深层文件，过程资料还有独立路由。它提示我们：长期保存不代表每次都加载，保存操作经验也不等于允许自动执行。文件组织的具体读取路径见[上下文路由](../05-retrieval-context/04.md)。[R15][固定版本源码](https://github.com/letta-ai/letta-code/blob/bd31b0a72dfad1ba14fc3a82f47da6a2b606330d/src/backend/local/system-prompt-compilation.ts#L65-L198)。

### 2.2.7 用户记忆、项目记忆与 Agent 记忆

#### 内容类型、保留用途和归属是三条不同轴

“u1 上次在 Atlas 遇到角色错误”可以是长期保留的个人情景记忆；“本轮已找到的项目术语定义”可以是工作上下文中的语义内容。长期与情景不是互斥标签，项目与语义也不是同一级分类。

参考建模可分别记录 scope、retention_policy 和 content_kind，不必为所有组合建立独立服务。查询时先检查主体和项目，再按任务需要选择内容类型；清理时依据保留政策，而不是看到 episodic 就一律丢弃。

归属还影响共享。同一事故的私有记录可能含个人反馈，团队版经验只保留故障条件和可验证处理。团队版是经过筛选的新派生物，不是给私有记录换一个目录。它要有独立身份、来源关系和更正路径；原始归因被推翻时，共享方法也需重新核对。

用户记忆影响个人交互，项目记忆服务授权团队，Agent 记忆可记录特定角色的经验。使用同一模型或向量库，不构成自动共享的理由。

个人偏好不能因被写入项目总结就公开；任务轨迹提升为团队经验前，应去除不必要信息并重新审核授权。

三轴分类可以形成组合键，但不应变成组合爆炸的枚举表。例如 scope=user/u1，retention=long_term，content=episodic 表示长期保存的用户事件；scope=project/atlas，retention=working，content=semantic 则可表示本次任务选中的项目事实。访问层按不同轴过滤，无需为每个组合建立独立服务。

保留层次的转换也要有策略：短期摘要晋升长期记忆时重新判断价值与授权，而不是达到某个存活天数后自动升级。长期记录退出活跃索引也不一定等于删除原始事件。
