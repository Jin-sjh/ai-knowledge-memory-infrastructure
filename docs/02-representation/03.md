# 2.3 信息的管理维度

[全书首页](../../README.md) · [本章导读](README.md)

> 概念说明与参考设计，非已实现系统报告。核验日期：2026-11-13。

## 要解决的问题

哪些管理字段决定能否使用信息？

可用集合是当前主体有权访问、查询时间有效且状态允许使用的对象集合，而非相似记录全集。元数据是访问约束，不只是显示信息。

### 2.3.1 语义类型与用途

语义类型回答内容是什么，用途回答准备用它做什么。事故记录既可用于历史查询，也可作为排查线索；用于自动审批则需要另一类规则依据。

允许多用途，但应分别定义进入条件。“能被检索”不等于“允许驱动动作”，用途标签必须对应具体处理责任。

### 2.3.2 作用范围与归属

归属回答属于哪个用户、项目和组织。相同文本位于不同租户时，更新、授权与删除责任仍可能不同，不能只因内容一致就合成共享对象。

查询范围从可信身份与成员关系派生，不能把客户端任意传入的用户 ID 当成授权证明。字段组织数据，策略决定可见性。

### 2.3.3 来源、出处及证据关系

来源标识指向输入材料，出处定位指向具体段落，证据关系说明段落支持哪个命题。只有 URL，在页面更新后无法解释旧答案；只有摘录，又可能失去版本与权限。

参考表示把来源版本、定位和命题版本一起保存。定位成立仍不证明支持关系正确，还需核对否定、范围和条件。

### 2.3.4 时间属性与有效期

有效时间是业务上何时成立，记录时间是系统何时知道。周三生效的规则周五才同步时，周四的真实规范与系统当时认知并不相同。

因此采集、修改与生效应分别记录。历史查询先说明采用哪种时间；有效期缺失时保留未知，不能用导入时间补出事实。

文档哈希变化只说明输入快照不同，不能直接推出业务生效时间。LlamaIndex 按标识和哈希决定重处理，因此接入规范系统时，应从业务字段解析有效期，而非把索引更新时间视作规则生效日。缺少有效期时保留未知并要求确认。[固定版本源码](https://github.com/run-llama/llama_index/blob/baeabbfe26241a6916e13e2a8c8156a02e0602cd/llama-index-core/llama_index/core/ingestion/pipeline.py#L469-L507)。

有效时间与记录时间构成两条不同时间轴。假设新规范 11 月 1 日生效、11 月 3 日才入库，查询“11 月 2 日实际规则”应使用新规范；查询“系统在 11 月 2 日当时知道什么”则只能依据当时已登记来源。支持后者需要保留记录历史，当前快照不足以重建。

本书 JSON 样例只展示当前记录及有效区间，不宣称实现完整双时态数据库。实现者若需要审计历史认知状态，应增加 transaction_from/transaction_to 或不可变事件投影，而非复用 valid_from。

### 2.3.5 可信状态与验证等级

可信状态应说明检查到哪一步，如仅记录陈述、证据已定位、已通过领域审核。待核实故障可作为线索，不能因此修改正式规范。

单个分数无法解释所有问题：来源可靠但过期，与信息很新但缺少佐证，需要不同处理。状态和缺口应随访问结果返回。

置信分不能抵消授权限制，也不能跨来源不经校准比较。

### 2.3.6 敏感性、访问权限与授权

敏感性描述内容风险，权限说明谁可读取，授权还要检查本次用途。例如公开文档和私有偏好生成的摘要，不能仅因包含公开资料就公开。

派生物要登记输入依赖；扩大共享范围时重新检查或生成合适视图，不能只改 scope 标签。

### 2.3.7 生命周期与版本

内容修订、可见性变化和物理清理是不同事件。v2 替代 v1 后，v1 可能仍可用于授权历史查询；删除请求则可能要求所有副本停止使用并最终清理。

内容版本定位当时文本，生命周期状态决定现在允许什么。只有 latest 指针而无历史状态，难以解释旧答案或核对删除进度。
